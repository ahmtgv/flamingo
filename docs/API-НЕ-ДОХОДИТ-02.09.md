# Почему api.flamingo.plus молчит у владельца, а на сервере отвечает за 20 мс

Владелец: «сервер не откликается — причина в чём может быть?» и дважды: «проблема
может быть в cloudflare — опять я говорю».

## Что померено, по порядку

| Замер | Результат | Что снимает |
|---|---|---|
| `journalctl -u flamingo` за 14 ч | ноль `WORKER TIMEOUT`, ноль падений | «работники залипли» — **неверно** |
| `curl http://127.0.0.1:8000/api/auth/me` | **200 за 6 мс** | Django здоров |
| сеть контейнера Caddy | `flamingo-prod_default gw=172.18.0.1` | совпадает с привязкой gunicorn |
| `wget` из контейнера Caddy на `172.18.0.1:8000` | `400 Bad Request` — **ответил Django** | провод Caddy→gunicorn цел |
| ufw | правило 7 пропускает `172.18.0.0/16` → 8000 | не режет |
| `curl --resolve api.flamingo.plus:443:127.0.0.1` | **200, tls 10 мс, всего 20 мс** | «Caddy потерял сертификат» — **неверно** |
| лог Caddy, ACME | `cert_expiry` ноябрь 2026 для api и files | сертификаты живы |
| **лог Caddy, входящие** | только сканеры (94.154.46.247, 195.182.16.23, 223.123.43.32, 160.250.181.123). **Ни одного запроса из браузера владельца** | запросы до сервера **не доходят** |

Из браузера владельца, чистая вкладка:

    https://82.147.71.204/       → ответ TLS за 955 мс   ← сервер достижим
    https://api.flamingo.plus/   → молчит 6221 мс
    https://files.flamingo.plus/ → молчит 6999 мс
    DNS: api и files → 82.147.71.204 (верно, серое облачко)

## Вывод

Тот же адрес, тот же порт. **По цифрам — отвечает за секунду. По имени — не доходит
вовсе.** Разница между этими двумя рукопожатиями ровно одна: во втором в открытом
виде передаётся имя узла (SNI). Рвётся дорога, и рвётся по имени.

Согласуется со всем остальным за день:

- ssh на тот же адрес (порт 22, имени в пакете нет) работает — владелец сейчас на нём;
- `flamingo.plus` (Cloudflare Pages, чужие адреса) работает;
- оранжевое облачко утром «вылечило» ровно это место: 6480 мс → 216 мс. Не потому что
  Cloudflare быстрее, а потому что трафик тогда шёл не на этот адрес.

## Про Cloudflare — прямо

Сейчас Cloudflare **не в дороге** до `api`: запись серая, браузер идёт на наш адрес
напрямую. Так что причина не в нём. Но починка, скорее всего, лежит именно в нём — и
это разные вещи, которые легко перепутать.

## Чего мы НЕ знаем

Один замер не сделан: тот же адрес с другого провайдера. Пока он не сделан, «дорога у
владельца» — сильная версия, а не факт. Проверяется телефоном на мобильном интернете
за минуту.

## Что НЕ подтвердилось (мои версии, обе)

1. «Все работники gunicorn заняты» — снято логом.
2. «Caddy потерял сертификат и висит на выпуске» — снято ответом за 20 мс по имени.

Обе были высказаны как версии и обе проверены до правки, а не после. Ничего по ним
не менялось.
