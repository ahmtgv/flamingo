# ADR-001 — Как backend живёт внутри десктопного приложения

**Статус:** принято по итогам спайка · **Дата:** 2026-08-14 · **Фаза:** Р5.2
**Контекст:** PROMPT_14 §Р5.2 · OWNER_SCOPE §18 · `R5_DESKTOP_HOST_BUDGET.md` §5

---

## Решение

**Django как sidecar-процесс на SQLite, слушающий 127.0.0.1, внутри оболочки Tauri; React грузится
из бандла.** Рабочая гипотеза промпта проверена и выдержала — с одной находкой, которую пришлось
чинить, и одним вопросом, который спайк открыл заново.

Все числа ниже — из прогонов, а не из опыта. Скрипты приложены к разделам.

---

## 1. Мигрируются ли миграции на SQLite

**Да, целиком. И весь домен работает на SQLite — 468 тестов из 468.**

Это самая сильная проверка, какая у нас есть, и она была почти бесплатной: `config/settings_test.py`
уже описывал SQLite in-memory, но pytest шёл по `config.settings`, то есть по Postgres. Достаточно
было запустить тот же набор против другого бэкенда.

```
DJANGO_SETTINGS_MODULE=config.settings_test pytest   →  468 passed
DJANGO_SETTINGS_MODULE=config.settings     pytest   →  468 passed
```

Чистая миграция на файловую базу (`config/settings_desktop.py`):

| | |
|---|---|
| `django.setup()` | **0,44 с** |
| `migrate` на пустом файле | **0,93 с** |
| миграций применено | 51 |
| таблиц создано | 64 |
| пустой кабинет на диске | **1,2 МБ** |

### Что не переносится — и как обошли

**Нативных enum нет и не было.** ERD говорит про «Postgres native enums», но код с самого начала
писался на `CharField(choices=...)` + `common/enums.py` как единственный источник. Django на SQLite
кладёт то же самое в `varchar` с `CHECK`. Переносить нечего.

**JSONB переносится.** `JSONField` на SQLite — это `json_valid()`-текст плюс `json_extract` в
лукапах. Все наши обращения к JSON — чтение целого поля в Python (`payload`, `source_meta`,
`answer_key`, `elements`), ни одного лукапа внутрь JSON. Переносится без изменений.

**UUID PK переносится.** `char(32)` вместо `uuid`; для нас важно только то, что идентификатор
устойчив и генерируется клиентом (OWNER_SCOPE §18, требование «а»), а это свойство `uuid4`, а не
типа колонки. Частичные уникальные индексы (`uniq_direct_channel`, `uniq_lexical_sense`) и
`CheckConstraint` (`lexical_item_is_attributed`) SQLite поддерживает — они в тех самых 468 тестах.

**🔴 Единственная реальная поломка: `icontains` по-русски.** Поиск в каталоге по «биолог» не находил
«Биология». SQLite складывает регистр в `LIKE` только для ASCII; Postgres на `ILIKE` — для всего
Unicode. Тихо: пользователь получает пустой список и ни одного сообщения о том, почему.

Починено тем, что SQLite разрешает приложению подменить `like` своей функцией, а `str.casefold()`
в Python знает весь Unicode: `common/sqlite_unicode.py`, регистрируется из `CommonConfig.ready()`.
Регистрируется **и для тестов тоже** — иначе разница между тем, на чём гоняют тесты, и тем, на чём
работает преподаватель, обнаруживается только преподавателем.

### Чего спайк не трогал и почему

**Одновременная запись.** У sidecar один процесс и один писатель. Включён WAL, `timeout=20 с` —
этого хватает для «доска пишет, отчёт читает». Если Р5.7 (планшет как перо) даст второй поток
записи в ту же базу, число надо перемерить; сейчас мерить нечего.

## 2. Вес и старт

**Собрано по-настоящему (Р5.3): `cargo tauri build`, Rust 1.95, tauri-cli 2.11.4, macOS aarch64.**
Три числа, которых здесь не хватало, теперь измерены, а не оценены.

### Установщик и вес (измерено)

| Часть | Размер | |
|---|---|---|
| **`.dmg`, то что скачивает преподаватель** | **59,4 МБ** | 62 337 609 байт, UDZO |
| **`Flamingo.app`, то что лежит на диске** | **92 МБ** | |
| — оболочка: Rust + весь фронтенд внутри бинарника | 8,67 МБ | `opt-level="z"` · LTO · strip |
| — sidecar (PyInstaller, папкой) | 83 МБ | на диске 66 МБ, см. находку ниже |
| фронтенд: 8 файлов, 16,8 МБ сырых | ≈4,2 МБ | Tauri жмёт brotli при вкладывании |
| — из них `vision_wasm_module_internal.wasm` | 11,2 МБ | MediaPipe |
| — `face_landmarker.task` | 3,76 МБ | MediaPipe |
| пустой кабинет | 1,2 МБ | |

Все восемь файлов `dist` действительно попали в бинарник — проверено поиском имён в собранном
исполняемом файле, а не тем, что сборка не ругнулась.

**Находка на 17 МБ: Tauri разыменовывает симлинки.** В выводе PyInstaller четыре симлинка внутри
`Python.framework` (`Versions/Current` и спутники). Копируя ресурсы, бандлер кладёт по каждому
настоящий файл, и фреймворк Python уезжает в сборку дважды: `du` — 66 МБ, `du -L` — 83 МБ. Ровно эти
17 МБ и есть разница. Чинится плоской раскладкой sidecar или хуком бандлера; записано, не сделано —
это вес, а не поведение, и лезть в раскладку сборки посреди фазы про раму нечестно.

> ⚠️ **Числа веса ниже устарели на +13 МБ (Р5.5).** Кабинет одним файлом шифруется AES-GCM,
> и `cryptography` вернулся в десктопный набор: `site-packages` 74 → **87 МБ** (замерено;
> сам пакет 13 МБ). Установщик и `.app` не перемеряны — это отдельная сборка, и выдумывать
> тут число я не стану. Sidecar на новом наборе проверен: `setup 0,53 с · migrate 0,90 с ·
> выгрузка кабинета 2,25 с`, `boto3` по-прежнему не загружается.

### PyInstaller против venv (измерено)

| | PyInstaller | venv |
|---|---|---|
| вес | **66 МБ** | 74 МБ `site-packages` **+ 72 МБ** интерпретатор и stdlib ≈ **146 МБ** |
| холодный старт → первый ответ GraphQL | **0,13 с** | 0,88 с |
| тёплый запрос | 1,8 мс | 1,1 мс |
| нужен Python на машине преподавателя | нет | да, либо везти свой |

**Вердикт: PyInstaller.** Вдвое легче и в семь раз быстрее стартует. Причина второго — весь Python
лежит одним архивом с уже скомпилированными `.pyc`, вместо обхода дерева `site-packages` на импортах.

Две вещи, которые пришлось починить, чтобы это вообще собралось, и обе стоят того, чтобы быть
записанными: uvicorn нельзя давать приложение строкой `"config.asgi:application"` — во фрозен-бандле
нет дерева исходников, из которого он его импортирует, и приложение передаётся **объектом**
(`sidecar_entry.py`); а модули настроек PyInstaller не находит сам, потому что Django берёт их по
имени из переменной окружения — они перечислены явными `--hidden-import`.

### Первый запуск после установки (измерено — и с честной оговоркой)

```
установлено в /Applications, запуск двойным щелчком (open -n)
запуск 1 (первый после установки) → ответ GraphQL   2,20 с
запуск 2                                            1,17 с
запуск 3                                            1,12 с
то же с карантинным атрибутом (как после скачивания) 1,79 с / 1,55 с
```

**Оговорка, без которой число вводит в заблуждение.** Карантинный атрибут на машине, где сборка и
родилась, не воспроизводит первую встречу Gatekeeper с чужим бинарником: там добавляется сетевая
проверка нотаризации и диалог «разработчик не подтверждён», а он не про секунды, он про то, что
приложение вообще не откроется, пока человек не разрешит его руками. Это цена решения §19.2, и
предупредить о ней обязана страница загрузки (D6).

**И одно наблюдение, которое опаснее среднего.** Самый первый в жизни запуск свежезаписанного вывода
PyInstaller занял **17,84 с** — разовая проверка macOS двух сотен неподписанных `.dylib`; следующие
запуски тех же файлов укладывались в 0,13 с. После установки в `/Applications` эта цена уже не
платилась (2,2 с). Я **не берусь утверждать**, какой из двух сценариев увидит преподаватель на своей
машине в первый раз, — это меряется на машине, которая этих файлов не видела, и такой машины у меня
нет. Поэтому рама обязана пережить худший: экран запуска со словами, а не белое окно на восемнадцать
секунд (это требование к листу D1, а не пожелание).

## 3. Обновление sidecar вместе с оболочкой

**Одна сборка, одна версия.** `common/desktop.py`: `DESKTOP_VERSION` (оболочка + sidecar вместе) и
`CABINET_SCHEMA_VERSION` (поколение схемы кабинета).

Правило, ради которого всё это заведено, одно и касается **отката**: новая сборка, открывающая
старый кабинет, — обычный случай, она его мигрирует. Старая сборка, открывающая **новый** кабинет, —
опасный: ничего не падает, просто колонки означают уже другое. Поэтому `refuses_cabinet()`
отказывается стартовать, если кабинет мигрирован более новым поколением. Один раз неприятно; молча
неверная оценка неприятна долго, и никто не знает, что надо смотреть.

`UpdateManifest` (версия · поколение схемы · адрес · заметки · обязательность) — то, что публикует
релиз и опрашивает оболочка. Поле `mandatory` существует потому, что миграция кабинета не может быть
необязательной: установленная база, расползшаяся по двум поколениям схемы, — это поддержка без дна.

Как обновление **доставляется** — лист **D6**, он не нарисован. Здесь зафиксирована форма, которую
он будет читать, и проверка, которую sidecar выполняет.

## 4. Что спайк открыл сверх трёх вопросов

**Объектного хранилища на десктопе нет.** Модуль `files` построен на presigned S3 URL. На ноутбуке
S3 нет и не будет. `common/storage.py` получил второй бэкенд — файлы рядом с базой, в папке кабинета —
и переключается **конфигурацией** (`STORAGE_BACKEND`), а не `if`-ом на месте вызова и не хардкодом
«на десктопе всё локально» (OWNER_SCOPE §18, требование «г»).

Это же чинит красный долг Р5.2: зеркало ученика теперь **физически копирует** файлы работ в хранилище
точки встречи, в пространство имён самого ученика, а не ссылается на ключ, который после переезда
базы будет указывать на компьютер преподавателя.

## 5. Альтернативы, которые рассматривались

| Вариант | Почему не он |
|---|---|
| **Переписать backend на Rust/Tauri-native** | Выбрасывает модели, сервисы, права и 468 тестов — то самое переиспользование, на котором построена экономика решения (`R5_DESKTOP_HOST_BUDGET.md` §5). Экономия ≈100 МБ веса против месяцев работы и нового набора ошибок в правах доступа. |
| **Postgres, встроенный в приложение** | +150 МБ, отдельный процесс с собственным жизненным циклом и своя история отказов при выключении ноутбука крышкой. Взамен — совместимость, которая по итогам §1 и так есть. |
| **Electron вместо Tauri** | Тянет Chromium (~120 МБ) поверх того же sidecar. Промпт называет Tauri, и спайк не нашёл причины спорить. |
| **venv вместо PyInstaller** | Проверено в Р5.3 и проиграло по всем осям: 146 МБ против 66, старт 0,88 с против 0,13 с, и нужен Python на машине преподавателя. См. §2. |

## 6. Что осталось и требует решения

1. ~~**Реальная сборка Tauri**~~ — сделана в Р5.3, числа в §2.
2. ~~**Отдельный `requirements-desktop.txt`**~~ — есть, 118 → 74 МБ. `boto3` выброшен **по факту**, а
   не по списку: sidecar не подписывает запросы к хранилищу, он кладёт файл по presigned-ссылке,
   которую подписал сервер, а это обычный HTTPS-PUT из стандартной библиотеки
   (`apps/meetingpoint/transfer.py`). Отсутствие проверяется тестом, а не комментарием.
3. ~~**PyInstaller против venv**~~ — измерено, §2. PyInstaller.
4. **Второй писатель в SQLite**, если Р5.7 приведёт планшет к той же базе. Решением владельца §21.2
   планшет **не пишет в базу** — значит, второго писателя не будет; перемерить придётся, только если
   это решение изменится.
5. **Подписи установщика** — отложено решением владельца 14.08 (§19.2); страница загрузки обязана
   предупредить про «неизвестного разработчика» (текст — D6). Цена решения теперь измерена в §2:
   на чужой машине это не секунды, а диалог, который блокирует запуск до ручного разрешения.
6. **17 МБ на разыменованных симлинках** `Python.framework` (§2). Плоская раскладка sidecar или хук
   бандлера; вес, не поведение.
7. **Иконка приложения — заглушка.** Собрана из одного токена `--fl-coral-500`; в атласе листа с
   иконкой нет, а придумывать её вместо дизайна — это ровно то, что CLAUDE.md §11 запрещает делать
   с утверждёнными экранами. На вес установщика не влияет.
