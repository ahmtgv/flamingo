## 1. 🔴 СЕССИЯ НЕ ПЕРЕЖИВАЕТ МОРГАНИЕ СЕРВЕРА

Твоя находка, и она худшая за месяц: полминуты недоступности посреди урока — и весь класс
вводит пароли заново.

**Причина найдена, она в одном месте.** `frontend/src/shared/lib/refresh.ts:55-60`:

```js
  } catch {
    /* сеть отказала или вышел таймаут — падаем в очистку */
  } finally { clearTimeout(timer); }
  clearSession();
```

`clearSession()` стоит **после** `try`, то есть выполняется при любом исходе, кроме успеха.
Сеть отказала, таймаут вышел, сервер ответил 502 — ключи стёрты навсегда. Комментарий
показывает, что это был осознанный выбор; выбор неверный.

🔴 **Правило, которое надо внести:** «сервер не ответил» и «тебя не признали» — **разные
события**, и лечатся они по-разному. Тот же класс, что весь этот месяц: уверенное неверное.

**Чистить сессию только тогда, когда сервер ЯВНО сказал, что ключ обновления недействителен.**
Сеть, таймаут, 5xx, разорванное соединение — ключи остаются, продукт ждёт и пробует снова.

Что должно получиться на экране: человек видит, что связи нет, **и остаётся там, где был**.
Связь вернулась — работа продолжается без единого нажатия.

**Доказать провалом:** двое в комнате, сервер убран на минуту, поднят обратно. Никто не увидел
формы входа, оба продолжили урок. Замерь хранилище до, во время и после — как ты и делал.

⚠️ Проверь заодно **все остальные места, где чистится сессия**: если где-то ещё отказ сети
читается как «выйти», болезнь вернётся с другой стороны.
