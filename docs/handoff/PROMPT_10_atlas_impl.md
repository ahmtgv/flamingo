## 1. Незыблемое (guardrails — нарушать нельзя)
- **AIR-токены** (`tokens.css`) — никаких raw hex/px; `shared/ui` примитивы; icon/content/blur токены (из аудита).
- **i18n** — ни одной hardcoded кириллицы в TSX; все ключи в `ru/*.json`.
- **Типы** — все операции на сгенерированных типах (`@/entities/graphql/generated`); **ноль `any`**; после изменений схемы — `npm run codegen`.
- **a11y** — WCAG 2.1 AA: фокус-ринги, ARIA, клавиатура, `prefers-reduced-motion`, контраст; настоящие `<button>`.
- **Состояния** — на КАЖДОМ экране: пусто · skeleton · **ошибка (используй `ErrorState` из аудита)** · заполнено · переполнено (свёртка «Ещё N…» с 10).
- **Тёмная тема** и **kids-режим** — паритет.
- **Глобальные решения владельца:** внимание live → только учителю; сводка внимания → только ЛК (лист 10), НЕ на дашборде; аналитика внимания преподавателю — после занятия/из настроек, НЕ на дашборде; цену/«бесплатно» не упоминаем нигде (место под цену в aside курса заложено); расписание — дефолт список + переключатель список/неделя/месяц; отменённые видимы + «скрыть отменённые».
- **Двойной режим (критично):** каждый экран работает И в реальном режиме (против бэкенда), И в демо (`VITE_PREVIEW=1`, flamingo.plus). **Демо-слой (`frontend/src/shared/demo/`) расширь под ВСЕ новые/изменённые запросы и проекции — иначе на flamingo.plus новые экраны будут пустыми.** Демо-линк остаётся терминирующим (ноль сетевого эгресса).
- **Не ломать:** фиксы аудита №9, инвариант приватности (8 скаляров, эгресс не трогать), `VITE_PREVIEW`/демо-слой, правила видео (без remount `<video>`, `track.enabled`), пер-резолверную авторизацию (только свои данные).
- **Гейты зелёные каждая** (база: backend 102 pytest / frontend 135 vitest; ruff/black/eslint/tsc/build). **Один концерн — один коммит**, Conventional Commits.

## 2. ФАЗА A — Лист 03 (кабинет преподавателя)
**Контракт (лист 03):** экран отвечает на вопрос «что требует меня прямо сейчас?» тремя числами:
**занятия сегодня · непроверенные ДЗ (кликабельная ЗАДАЧА — единственный коралловый акцент спокойного дня) · ученики**;
ниже — сегодняшние занятия и мои курсы; **live-занятие перехватывает акцент на себя**; состояния: обычный день / идёт занятие / новый преподаватель / skeleton / error.

**⚠️ Данных не хватает — добавить ТОНКО (это core-workflow, не отложенная фича; хостинг не нужен — демо-слой отдаёт то же на flamingo.plus):**
- **«непроверенные ДЗ»**: сейчас НЕТ агрегатного запроса (есть только per-lesson `LessonHomework` / per-homework `HomeworkSubmissions`). Добавь тонко: сервис + резолвер **очереди проверки преподавателя** (ожидающие проверки сдачи по курсам, где он владелец) + счётчик. Логика в `apps/homework/services.py`; пер-резолверная авторизация (только свои курсы). Клик по метрике ведёт на очередь проверки (карточка проверки уже есть: `GradeSubmission`/`LessonHomework`). SDL — **hand-add** нового поля (форвард-контракт §10: свериться с live-схемой `export_schema`, дописать вручную, НЕ `export_schema`-регенерацией). `npm run codegen`. +тесты (вкл. права: чужую очередь не видно).
- **«ученики»**: счётчик distinct-учеников преподавателя — тонкий резолвер/агрегат.
- **«занятия сегодня»** и **«мои курсы»** — из существующих `MySchedule`(today)/`MyCourses`.
- **Демо-слой:** отдать эти же формы (очередь проверки, счётчики, сегодняшние занятия) синтетикой для роли teacher.

Реализуй `TeacherCabinet.tsx` строго по листу 03 (три метрики, акцент-логика, live-перехват, сегодняшние занятия, мои курсы, все состояния). Скриншот-паритет.
