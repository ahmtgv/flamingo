## 1. НЕЗЫБЛЕМЫЕ ИНВАРИАНТЫ (критерий корректности, НЕ предмет уборки — нарушать нельзя)
1. **Приватность on-device (SEduM).** Ни один серверный путь не принимает сырое видео/аудио/кадры/landmarks/пер-кадровые фичи. С устройства уходит ТОЛЬКО пер-бакетный агрегат из 8 скаляров `{sessionId, studentId(из auth, не из ввода), bucketStart, avgAttention, gazeOnScreen, eyeOpenness, headYaw, headPitch, alertness}`. Суб-метрики — live-only (broadcast, не персистятся); в БД хранится только `avg_attention`. UBP — в IndexedDB; облачный бэкап — client-encrypted (сервер хранит непрозрачный blob). **Должен существовать тест-инвариант: ни один resolver/endpoint не принимает сырое медиа.** Если теста нет — добавить.
2. **152-ФЗ residency.** PII — только РФ-хранилища; `consent152fz` при регистрации для <18. Не вводить хранилища PII вне РФ.
3. **i18n.** Никаких hardcoded UI-строк — всё через i18n. Локаль `ru` единственная в поставке, но код locale-agnostic.
4. **Дизайн-токены.** Никаких hardcoded цветов/размеров/шрифтов — только семантические токены `tokens.css` (AIR v2).
5. **Только open-source.** Никаких проприетарных зависимостей.
6. **Отложенное НЕ строить** (blockchain/NFT, VR/AR, Open API, Neo4j, native mobile). Наличие следов — можно отметить, реализовывать — нельзя.
7. **Авторизация — пер-резолверная, серверная.** Никогда не доверять клиентской роли/id. Доступ к контенту — через единый чокпоинт `courses/access.py::can_access_course`.
8. **Payment-ready швы** (`Enrollment.access_status`, `Course.price/currency`) — уважать, не обходить. Billing не построен и СЕЙЧАС не строим.
9. **Намеренно-временный код НЕ считать мёртвым и НЕ удалять:** флаг `VITE_PREVIEW` (+ `enterPreviewSession`/`bootstrapSession` ветка), модуль `frontend/src/shared/demo/**` (демо-слой, если уже влит промптом №8), `CmfDebugHud` (`?cmfDebug=1`). Распознать и сохранить.
10. **SDL — форвард-контракт.** `docs/flamingo_schema.graphql` поддерживается вручную; поля без текущего резолвера могут быть намеренным будущим контрактом, а не гнилью. SDL и `docs/**` **не править разрушительно** — drift только фиксировать в отчёт (пер-поле, с доказательством). Codegen во фронте регенерировать можно.

## 6. ТРЕК C — SEduM / CMF (алгоритмика + приватность)
Проанализировать глубоко и починить БЕЗОПАСНОЕ; полноценный ре-R&D (SEduM-NG) — отдельная запланированная задача, СЕЙЧАС НЕ ПЕРЕПИСЫВАТЬ.
- Подтвердить/углубить корневые причины: **C-RC1** база-линия калибровки никогда не вшита → скоринг на некалиброванной шкале блендшейпов (архитектурная); **C-RC2** gaze из 8 eye-look блендшейпов груб, iris-landmarks не используются; **C-RC3** пер-кадровое EMA квантуется в int до усреднения → ступени; **C-RC4** кадры без лица пишутся как 0 и тянут бакет вниз; **C-RC5** пороги/head-pose шум/5fps на setTimeout дрейфит.
- **Безопасные фиксы сейчас (не ребилд):** «нет лица» → `null`, не 0 (устранить zero-pollution в знаменателе бакета); clamp/защита агрегатов; согласовать с backend-clamp. Всё, что меняет качество скоринга структурно (iris-gaze, калибровка-first, гистерезис) — оставить для SEduM-NG, только описать в отчёте как gap.
- **Приватность** — воркер считает локально; эгресс = ровно 8 агрегатных скаляров; суб-метрики live-only не персистятся; кадры/landmarks/пер-кадровые фичи никуда не постятся; UBP в IndexedDB; облачный бэкап client-encrypted. Любое отклонение — CRITICAL.
- **Устойчивость воркера** — lifecycle, вендоренный WASM (module worker), staleness-отображение (`liveAttentionStaleMs`), поведение при троттлинге вкладки.
- **Eval-harness** — если численного harness (fake-camera + ground-truth видео → метрики качества в CI) нет, зафиксировать как gap (не строить здесь — часть SEduM-NG). Учесть, что D0-замеры владельца ещё ожидаются.
