## A. BACKEND — безопасность и архитектура

### CRITICAL (чинить немедленно, промпт №2)
- **A-C1. `lesson`-query не гейтится:** любой аутентифицированный пользователь может получить контент урока без enrollment (`apps/courses/graphql/queries.py :: lesson` — известный TODO в `access.py`, но это дыра уже сейчас). Фикс: маршрутизировать через `can_access_course`.
- **A-C2. `Group.students` / `Group.teachers` отдают ростер (ФИО/контакты — PII несовершеннолетних) не-админам** — тот же класс, что закрытая attendance-дыра `b2782ba`. Фикс: пер-резолверная проверка (только админ своего учреждения / преподаватель группы), иначе `[]`.
- **A-C3. `join_session` игнорирует `access_status` и групповую доставку** (`scheduling/services.py::_enrollment`): студент с `pending_payment` войдёт в эфир; студент группы без личного enrollment — НЕ войдёт. Фикс: маршрутизировать участие через `can_access_course` + ACTIVE-фильтр.

### HIGH
- A-H1. N+1 в ~6 field-резолверах (детские списки без select/prefetch_related) — производительность/DoS.
- A-H2. Отсутствуют индексы на горячих фильтрах (≥5 полей) + на `deleted_at`.
- A-H3. Refresh-токен (14 дней) не отзывается при logout — украденный токен живёт до истечения. Фикс: серверный revocation-список/ротация.

### Прочное (не трогать): soft-delete manager; гейтинг файлов материалов через chokepoint; auth подписки attentionUpdates; owner-namespace файлов; privacy-модель seedum (только агрегаты).

## C. SEduM — корневые причины «врут и скачут» (база для SEduM-NG)

Ранжированные root-cause гипотезы (подтверждать D0-замерами через `?cmfDebug=1`):

1. **C-RC1 [CRITICAL, архитектурная]. Базовая линия НИКОГДА не подключена:** калибровка «база тест» реализована и оттестирована, но UI не вшит → `baseline` всегда `undefined` → скоринг работает на некалиброванной шкале блендшейпов. «У всех врёт по-разному» — прямое следствие.
2. **C-RC2 [HIGH]. gazeOnScreen из 8 eye-look-блендшейпов груб по природе:** конфлатит наклон головы со взглядом-вне-экрана, деградирует на очках/свете; iris-landmarks модели НЕ используются, хотя доступны.
3. **C-RC3 [MED-HIGH]. Квантование EMA:** пер-кадровое EMA округляется до int сразу, потом усредняется в бакет — дискретные ступени вместо плавной кривой = «скачет».
4. **C-RC4 [MED]. Загрязнение нулями:** кадры без детекции лица пишутся как score=0 и утягивают средние бакета вниз (ложные провалы).
5. C-RC5. Константы AlertnessTracker/порогов не валидированы на живой камере; head-pose из матрицы шумный; 5fps-насос на setTimeout дрейфует при троттлинге вкладки.

**Вердикт keep/rebuild:** оставить — воркер-инфраструктуру (module worker + вендорённый WASM), бакетинг-каркас (починив нули/знаменатель), UBP-криптографию, privacy-контур целиком. Перестроить — метрики взгляда (iris-first), скоринг (калибровка-first + гистерезис/temporal smoothing вместо int-EMA), обработку «нет лица» как `null`, не 0.

**Рекомендуемая архитектура SEduM-NG (вариант-фаворит):** iris-landmark-first gaze + head-pose-secondary; обязательная калибровка при первом входе; временное сглаживание с гистерезисом (быстро вверх/медленно вниз) поверх float-величин; состояние «нет данных» первоклассно (никогда не 0); eval-harness: записанные ground-truth-видео + Chrome fake-camera → численные метрики качества в CI. Privacy-инвариант неизменен (эгресс — те же 8 агрегатных скаляров).
