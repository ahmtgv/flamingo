# `_redirects` — почему он такой, и почему рядом нет файла `404.html`

Файл `frontend/public/_redirects` управляет тем, что Cloudflare Pages отдаёт по каждому адресу.
Объяснения вынесены сюда, сам файл держится коротким.

---

## Что он делает

```
/graphql/*   /no-api.html   404
/graphql     /no-api.html   404
/api/*       /no-api.html   404
/*           /index.html    200
```

**Последнее правило — жизненно важное.** Одностраничному приложению нужно, чтобы любой адрес
отдавал `index.html`, иначе прямая ссылка вида `/link`, `/app` или приглашение `/j/english-a2`
упирается в «файла нет». Маршрутизацию дальше делает роутер в браузере.

**Первые три — исключение для API.** Правило `/*` перехватывало и `/graphql/`: Cloudflare отвечал
HTML, `HttpLink` пытался разобрать его как JSON и падал, а человек читал «что-то пошло не так»
и шёл чинить свой пароль вместо нашего деплоя (PROMPT_16 §А2, корневая причина R-01).

Исключение отдаёт **404, а не прокси на API**: адрес API живёт в переменной сборки
(`VITE_GRAPHQL_HTTP_URL`), браузер ходит туда напрямую, и на этом origin `/graphql/`
не должно быть вовсе. А прокси означал бы вписать домен в репозиторий, чего §9 не разрешает.

---

## 🔴 Почему страница называется `no-api.html`, а НЕ `404.html` (15.08.2026)

**Это не косметика. Имя файла ломало весь сайт.**

Пока файл назывался `404.html`, Cloudflare Pages отдавала его **на любой ненайденный путь,
не доходя до правила `/* → /index.html`**. Результат: на сайте не работала ни одна прямая ссылка —
ни `/link` (связывание машины), ни `/app`, ни приглашение ученика `/j/...`. Работал только корень,
а дальше человек ходил кликами внутри уже загруженного приложения — поэтому мы и не замечали
поломку неделями.

Нашлось это 15.08, когда владелец не смог перейти из десктопа на `flamingo.plus/link`
и увидел вместо страницы связывания текст «Здесь ничего нет. API живёт на другом адресе» —
то есть наш собственный файл 404.

⚠️ **Не создавать в `frontend/public/` файл с именем `404.html`.** Никогда. Пока в проекте
живёт SPA-фолбэк, этот файл выключает его целиком и молча.

### Что проверялось и оказалось ни при чём
- **Комментарии в `_redirects`.** Была гипотеза, что парсер Cloudflare спотыкается о шапку
  с эмодзи и кириллицей. Файл сократили до латиницы — не помогло. Гипотеза снята,
  но короткий файл оставлен: конфигурацию чужой платформы полезно держать минимальной.
- **Кэш браузера и Cloudflare.** Проверялось на прямых адресах сборки (`<хэш>.flamingo-c37.pages.dev`),
  минуя домен и кэш.
- **Сам файл.** Валидный UTF-8 без BOM, без CRLF, синтаксически верные правила, в `dist` попадает.
- **Деплой.** Сборка зелёная, коммит тот самый.

---

## Как проверить, что правило живо

После деплоя открыть прямой адрес сборки (минуя домен и его кэш):

```
https://<хэш>.flamingo-c37.pages.dev/link
```

**Должна открыться страница связывания.** Пришла страница «Здесь ничего нет» — фолбэк снова сломан.

Для сравнения `/graphql/` на том же адресе **обязан** отдавать 404 — иначе исключение потеряно
и вернётся R-01.

⚠️ Проверять надо **прямым заходом по адресу**, а не кликом внутри приложения: изнутри маршруты
работают всегда, потому что страница уже загружена. Именно поэтому поломка и жила так долго.
