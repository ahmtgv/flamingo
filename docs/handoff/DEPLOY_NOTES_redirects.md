# `_redirects` — почему он такой, и почему в нём нет объяснений

Файл `frontend/public/_redirects` управляет тем, что Cloudflare Pages отдаёт по каждому адресу.
Объяснения вынесены сюда, а сам файл держится **коротким и на латинице**. Причина — ниже.

---

## Что он делает

```
/graphql/*   /404.html   404
/graphql     /404.html   404
/api/*       /404.html   404
/*           /index.html 200
```

**Последнее правило — жизненно важное.** Одностраничному приложению нужно, чтобы любой адрес
отдавал `index.html`, иначе прямая ссылка вида `/link` или `/j/english-a2` упирается в «файла нет».
Маршрутизацию дальше делает роутер в браузере.

**Первые три — исключение для API.** Правило `/*` перехватывало и `/graphql/`: Cloudflare отвечал
HTML, `HttpLink` пытался разобрать его как JSON и падал, а человек читал «что-то пошло не так»
и шёл чинить свой пароль вместо нашего деплоя. Это самый дорогой вид поломки — она мимикрирует
под ответ сервера (PROMPT_16 §А2, корневая причина R-01).

Исключение отдаёт **404, а не прокси на API**. Две причины: адрес API живёт в переменной сборки
(`VITE_GRAPHQL_HTTP_URL`) и браузер ходит туда напрямую — на этом origin `/graphql/` не должно быть
вовсе; а прокси означал бы вписать домен в репозиторий, чего §9 не разрешает. 404 честен:
здесь API нет, и он больше не притворяется ответом сервера.

---

## 🔴 Почему в файле нет длинных комментариев (15.08.2026)

Ровно этот текст раньше лежал шапкой **внутри** `_redirects` — двадцать строк комментариев
с эмодзи и кириллицей. И правило `/* → /index.html` перестало применяться: прямой заход
на `/link` отдавал нашу же страницу 404, то есть Pages вела себя так, будто файла нет вовсе.

Проверено при разборе: файл был валидным UTF-8 без BOM, без CRLF, лежал в `dist`, содержал
четыре синтаксически верных правила. Единственным необычным в нём была эта шапка.

**Доказать, что виноват парсер Cloudflare, мы не смогли — и не пытаемся утверждать.**
Вывод сделан практический: конфигурационный файл чужой платформы держим минимальным
и на латинице, а рассуждения храним рядом, где им ничто не мешает.

⚠️ **Не возвращать комментарии в `_redirects`.** Если правишь файл — правь его коротким,
а «почему» дописывай сюда.

---

## Как проверить, что правило живо

После деплоя открыть прямой адрес сборки (минуя домен и его кэш):

```
https://<хэш>.flamingo-c37.pages.dev/link
```

**Должна открыться страница приложения.** Если пришла страница «Здесь ничего нет. API живёт
на другом адресе» — правило `/*` не работает, и это тот же дефект.

Для сравнения `/graphql/` на том же адресе **обязан** отдавать 404 — иначе исключение потеряно
и вернётся R-01.
