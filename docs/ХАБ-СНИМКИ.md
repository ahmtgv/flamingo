# Снимки источников хаба — как это устроено и как запустить на боевом

Решение владельца 10.09: превью в Flamingo HUB берутся **с самих источников**,
и ходит за ними **сервер**, а не браузер посетителя.

## Почему сервер, а не страница

Три причины, и каждая закрывает свой путь:

1. **Чужой сайт браузеру не отвечает.** Запрос со страницы `flamingo.plus` к
   чужому домену браузер блокирует (CORS). Прочитать `og:image` из вёрстки
   чужого сайта на клиенте нельзя в принципе.
2. **Ссылка прямо на чужую картинку — это слежка за нашими школьниками.**
   Поставь `<img src="https://чужой-сайт/...">` — и каждый, кто открыл титульную,
   лично сходит на тридцать шесть чужих серверов и покажет им свой адрес.
3. **Чужая картинка не нашего размера.** Одна 2560×1440 PNG на 4 МБ, другая
   600×315 JPEG. Шесть плиток витрины поедут кромками, а первый экран потяжелеет
   на мегабайты.

Сервер ходит раз в сутки, приводит всё к 640×360 JPEG и отдаёт **свои** файлы.

## Что где лежит

| что | где |
|---|---|
| каталог источников (одна правда) | `frontend/src/hub/sources.ts` |
| список для сервера (делается из каталога) | `backend/common/хаб-источники.json` |
| сама работа | `backend/common/снимки.py` |
| команда обхода | `backend/common/management/commands/хаб_снимки.py` |
| отдача | `backend/common/views.py`, адреса `api/hub/…` |
| прибор | `backend/common/прогон.py` |
| караул «список не разошёлся» | `frontend/scripts/хаб-список.mjs` |
| снимки на диске | `$MEDIA_ROOT/хаб/<id>.jpg` + `опись.json` |

Список для сервера руками не правится. Добавили источник в каталог —
`node scripts/хаб-список.mjs --записать`; караул в `npm run guards` не даст
забыть.

## Запуск на боевом

```bash
# 1. Pillow: без него чужую картинку не привести к одному размеру
cd /путь/к/flamingo/backend
.venv/bin/pip install -r requirements.txt

# 2. Проверка на себе — прибор не ходит в интернет, поднимает свой сервер
.venv/bin/python common/прогон.py

# 3. Разведка: сходить и рассказать, ничего не записывая
.venv/bin/python manage.py хаб_снимки --вхолостую

# 4. Первый настоящий обход (36 источников × пауза 1,5 с ≈ минута)
.venv/bin/python manage.py хаб_снимки --сила
```

Снимки лягут в `$MEDIA_ROOT/хаб/`. Проверить: `curl -sI https://api.flamingo.plus/api/hub/preview/hubble`
должен ответить `200` и `image/jpeg`, а `…/api/hub/previews` — списком имён.

## Раз в сутки

```ini
# /etc/systemd/system/flamingo-хаб.service
[Unit]
Description=Flamingo: снимки источников хаба
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
User=flamingo
WorkingDirectory=/путь/к/flamingo/backend
ExecStart=/путь/к/flamingo/backend/.venv/bin/python manage.py хаб_снимки
# Обход не должен уметь трогать ничего, кроме своей папки
PrivateTmp=yes
NoNewPrivileges=yes
ProtectSystem=strict
ReadWritePaths=/var/lib/flamingo
```

```ini
# /etc/systemd/system/flamingo-хаб.timer
[Unit]
Description=Flamingo: снимки источников хаба раз в сутки

[Timer]
OnCalendar=*-*-* 04:17:00
# Сервер лежал в 4:17 — сходить, как только поднялся, а не ждать сутки
Persistent=true
RandomizedDelaySec=900

[Install]
WantedBy=timers.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now flamingo-хаб.timer
systemctl list-timers flamingo-хаб.timer     # когда пойдёт в следующий раз
journalctl -u flamingo-хаб.service -n 50     # что вышло в прошлый
```

## Что происходит, когда что-то ломается

- **Сайт лежит.** Строка `✖ имя  ответил 503` в журнале, старый снимок остаётся
  на месте. Витрина не сереет из-за чужой аварии.
- **Сайт не объявил витрину.** `✖ имя  сайт не объявил витрину (нет og:image)` —
  у этого источника так и останется нарисованная обложка. Это не поломка.
- **Ни один источник не взялся.** Команда выходит с кодом 1, таймер красный:
  это уже не «сайт лежит», а «у сервера нет сети».
- **Обход ни разу не проходил.** `api/hub/previews` отвечает пустым списком,
  страница рисует обложки, как рисовала. Ничего не ломается.

## Что стоит знать про право

`og:image` — картинка, которую сайт **сам объявил** своей витриной для
пересылки по ссылке: ровно её показывают мессенджеры и соцсети. Мы делаем то же
самое и всегда называем источник рядом с картинкой. Если источник попросит так
не делать — он вычёркивается из каталога одной строкой, и снимок исчезает со
следующим обходом.
