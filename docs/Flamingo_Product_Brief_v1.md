## 1. Суть продукта

Flamingo — образовательная онлайн-платформа, объединяющая учеников, родителей, преподавателей и образовательные учреждения. Ключевая дифференциация — модуль SEduM: ИИ-анализ внимания и состояния пользователя для персонализации обучения, с принципом приватности «данные остаются у пользователя». Долгосрочное видение: блокчейн-верификация достижений, VR/AR, подключение научной инфраструктуры (лаборатории, обсерватории) через Open API.

Миссия: доступное качественное образование для каждого.

## 2. Целевая аудитория и модель

- **Модель:** B2C.
- **Ученики:** школьники 1–11 классов + слушатели курсов (включая языковые). Возрастной диапазон 7+ — интерфейс адаптируется: для младших классов аккаунтом управляет родитель, подростки и взрослые работают самостоятельно.
- **Родители:** покупатели и контролёры для младших учеников (кабинет родителя).
- **Преподаватели / репетиторы / учреждения:** создают контент (занятия, курсы, материалы) непосредственно на платформе. Конструктор курсов — критичная функция первой версии, не отложенная.
- Партнёры по контенту на запуск: в проработке (открытый вопрос).

## 3. Рынки, язык, юрисдикция

- **Рынки:** Россия и СНГ.
- **Язык MVP:** русский. Архитектура изначально i18n-ready (мультиязычность закладывается в код с первого дня, контент — позже).
- **Хранение персональных данных:** на серверах в РФ (требование 152-ФЗ). Облако — Яндекс Cloud.
- **Данные детей:** обязательное согласие родителей при регистрации учеников младше 18 лет.

## 4. Принцип «нода пользователя» (ключевое архитектурное решение)

- Сырые биометрические данные (видео с камеры, аудио с микрофона) **никогда не покидают устройство пользователя**.
- Анализ CMF выполняется on-device (в браузере / на телефоне) средствами open-source ML (MediaPipe и аналоги).
- На сервер передаются только обезличенные агрегированные метрики (уровень внимания, активность).
- UBP (биологический паспорт пользователя) хранится локально на устройстве.
- Опционально: зашифрованный резервный бэкап UBP в облако — только по явному согласию пользователя (защита от потери данных при смене устройства).

## 5. Состав MVP («расширенный MVP — выжимаем максимум»)

### Включено

**Роли и доступ**
- Регистрация и онбординг: ученик, родитель, преподаватель, администратор учреждения.
- Родительское согласие для несовершеннолетних.

**Ученик**
- Дашборд «Сегодня», расписание/календарь, журнал занятий.
- Онлайн-занятия (видео, демонстрация экрана, чат).
- Домашние задания: виртуальный рабочий стол (загрузка файлов, текстовые ответы).
- Учебные материалы, страница прогресса, профиль.

**Родитель**
- Сводка по ребёнку: расписание, оценки, прогресс, уведомления.

**Преподаватель**
- Конструктор занятий и курсов (полнофункциональный с первой версии).
- Расписание, библиотека материалов, журнал оценок, список учеников/групп.

**Администратор учреждения**
- Пользователи и приглашения, группы/классы, предметы, отчёты, настройки.

**SEduM Lite**
- «База тест» при онбординге (3-этапный видеотест базового состояния — авторская методика проекта).
- CMF on-device: метрики внимания во время занятий по камере/микрофону (MediaPipe).
- Поведенческая аналитика: активность, время занятий, результаты.
- Рекомендации на основе собранных метрик.

**Сертификаты**
- PDF-сертификаты с QR-кодом и страницей онлайн-верификации подлинности (архитектурный мост к будущему NFT/блокчейну).

### Отложено (по плану итераций из документации проекта)

| Функция | Итерация | Замена в MVP |
|---|---|---|
| Блокчейн / NFT | 4 | PDF + QR-верификация |
| VR / AR, геймификация | 3 | — |
| Open API (дроны, обсерватории, лаборатории) | 2 | — |
| Полный CMF (глубокий R&D биометрии) | R&D параллельно | CMF on-device на open-source моделях |
| Neo4j (графовая БД рекомендаций) | 2 | PostgreSQL |
| Кабинет научного сотрудника, центр управления образованием | 2–3 | — |

## 6. Технологический стек

| Слой | Решение |
|---|---|
| Backend | Django / Python, GraphQL (Graphene или Strawberry — выбор на этапе архитектуры), Celery, Redis |
| База данных | PostgreSQL |
| Frontend (web) | React, Redux Toolkit, Apollo Client |
| Видеозанятия | LiveKit (self-hosted, open source); альтернатива при проблемах — Jitsi |
| On-device ML | MediaPipe (анализ внимания в браузере/на устройстве) |
| Mobile | React Native (этап после стабилизации веба) |
| Инфраструктура | Docker; Kubernetes — после роста нагрузки; Яндекс Cloud; S3-совместимое хранилище (Yandex Object Storage) |

Принцип выбора инструментов: только open source высшего качества.

## 7. Очерёдность поставки

1. **Лендинг** — выпускается первым, собирает заявки и ранний доступ.
2. **Веб-приложение** — адаптивное (работает и на телефоне через браузер).
3. **Обкатка и стабилизация веба.**
4. **Мобильные приложения iOS/Android** (React Native) — после стабилизации API. Бонус мобильной версии: сдача ДЗ через камеру, push-уведомления, офлайн-материалы, в перспективе — мост к Bioimef через данные носимых устройств.

## 8. Дизайн-принципы

- Логотип создаётся заново.
- Главный критерий типографики и палитры: **долгое чтение без усталости глаз** — тёплый фон вместо чисто белого, спокойный контраст, шрифты с открытой апертурой, достаточный межстрочный интервал.
- Адаптивность под все экраны, доступность (ориентир — WCAG 2.1 AA).
- Возрастная адаптация интерфейса: младшие классы / подростки / взрослые.
- Современный чистый стиль без визуального шума.

## 9. Команда и процесс

- Состав: владелец продукта + Claude (Fable 5), разработка через Claude Code. Внешних разработчиков нет.
- Темп: максимально быстрый, без жёсткой даты релиза; не жжём время на второстепенное.
- Языки: общение и продуктовые документы — русский; код, комментарии, техническая документация (API spec, README, CLAUDE.md) — английский.
- На этапе архитектуры создаётся **CLAUDE.md** для репозитория — инструкции Claude Code: контекст проекта, стек, стандарты кода, структура.

## 10. Монетизация

Решение не принято — прорабатывается совместно. Кандидаты: подписка для учеников/родителей, комиссия с продажи курсов преподавателей, freemium. На лендинге до решения — блок «ранний доступ» вместо тарифов.
