## Устройство выката

```
flamingo.plus  ──►  Cloudflare Pages, проект «flamingo», аккаунт Derposte
                      ├── статика     ← frontend/dist (сборка Vite)
                      └── /api/room/* ← frontend/functions (функции Pages)

LiveKit                                ← медиа, ключи в переменных проекта
82.147.71.204                          ← НЕ ТРОГАЕТСЯ. Django на боевом не нужен вовсе
```

**Сервера в этом выкате нет.** Единственная работа бэкенда — подпись токена — делается
функцией Pages. Django остаётся для разработки.

## Почему ветка `v1`, а не `main`

Старый монорепозиторий существует теперь **только на GitHub**: локальную копию снесли
30.08. `force-push` поверх `main` уничтожил бы последнюю копию. Поэтому:

- новый проект уезжает в ветку **`v1`**;
- Cloudflare переключается на неё как на боевую;
- `main` со старым монорепозиторием остаётся нетронутым;
- **откат** — переключить боевую ветку обратно на `main`, одно поле в настройках.

## Шаг 1 — толкнуть код (делает владелец)

Из Cowork сети нет ни у меня, ни у машины через мост, поэтому это в обычном Терминале:

```bash
cd "/Users/piu/Claude/Projects/flamigo coworck"
git remote add origin https://github.com/ahmtgv/flamingo.git
git push origin main:v1
```

⚠️ **Пароль git на этой машине закэширован как `Ertconline`** — у него нет права записи,
push вернёт 403. Толкать надо от `ahmtgv`: либо стереть запись github.com в связке ключей
и войти заново, либо

```bash
git push https://ahmtgv:<ТОКЕН>@github.com/ahmtgv/flamingo.git main:v1
```

Токен владелец создаёт и вводит сам; ассистент токенов в руки не берёт.

## Шаг 2 — переменные окружения (вводит владелец)

Cloudflare → Pages → **flamingo** → Settings → Environment variables.
Добавить в **Production** и в **Preview** три строки:

| Имя | Что это |
|---|---|
| `LIVEKIT_URL` | адрес медиасервера, `wss://…` |
| `LIVEKIT_API_KEY` | ключ |
| `LIVEKIT_API_SECRET` | секрет |

Те же три значения лежат в `backend/.env`. **Значения вводит владелец сам.**

Проверить, что Node не старый: если сборка упадёт на Vite — добавить `NODE_VERSION` = `22`.

## Шаг 3 — предпросмотр, потом боевое

1. После push ветка `v1` соберётся **предпросмотром** — адрес вида `v1.flamingo-c37.pages.dev`.
   Боевое при этом ещё не тронуто.
2. Пройти путь на предпросмотре: два окна, ссылка, видео, звук, штрих на доске.
3. Только если прошло — Settings → Builds & deployments → **Production branch** → `v1`,
   и запустить выкат. flamingo.plus начинает отдавать новое.

## Проверка после выката

```
https://flamingo.plus/api/room/healthz   → {"ok":true,"livekit":true}
```

`livekit: false` означает, что переменные не доехали, — комната скажет об этом словами,
а не будет молча крутить «подключаемся».

Дальше — руками, в двух окнах: создать комнату, отдать ссылку, войти вторым,
проверить видео, звук, штрих и «стереть всё».

## Откат

Production branch → `main`, выкат. flamingo.plus возвращается к прежнему виду.

## Мина, найденная при сборке 30.08

Первая боевая сборка унесла в себе `http://localhost:8080` — адрес из локального
`frontend/.env`, который Vite читает во всех режимах. На боевом это мёртвая ссылка,
и заметить её можно было только по неработающей комнате. Починено в `src/lib/api.ts`:
на боевом адрес бэкенда не берётся из окружения вовсе, он всегда свой же.
