# 07 · Проверка и сводка: опровергнуть, свести, упорядочить

Запускается **после** сессий 01–06, когда их отчёты лежат в
`docs/АУДИТ-2026-10/отчёты/` и ветки `аудит/01…06` существуют.
Ветка `аудит/07-сводка`, результат — `docs/АУДИТ-2026-10/ОТЧЁТ.md` и
страница для владельца.

Цель: владелец получает **один** отчёт, в котором нет ни одной
неподтверждённой находки, ни одного повтора, и каждая строка заканчивается
решением, которое он может принять словом «да» или «нет».

🔴 Ты ничего не чинишь. Ты проверяешь чужое, сливаешь ветки с починками в
одну и отдаёшь владельцу. Единственные твои правки — в `ОТЧЁТ.md`.

---

## 1. Опровергнуть каждую находку

Прочитай шесть отчётов. Для **каждой** находки:

- воспроизведи её сам на названном кадре / командой / запросом, не читая
  доказательство автора, — потом сравни;
- вердикт: **подтверждаю** / **не воспроизводится** / **воспроизводится, но
  причина другая** (напиши какая) / **не проверял — почему**;
- проверь ссылку на правило или решение: правило существует и говорит именно
  это? решение владельца действительно есть в названном файле? Ссылка на
  несуществующее — находка снимается, автор об этом узнаёт из сводки;
- проверь категорию: «Ломает» — действительно нельзя сделать то, зачем
  пришёл? Понижай и повышай с обоснованием;
- проверь, что находка не повторяет другую из другого отчёта (одно и то же с
  двух осей — слить, сохранив оба доказательства).

Неподтверждённое в сводный отчёт не идёт — оно остаётся в отчёте сессии с
твоим вердиктом рядом.

## 2. Проверить починки

Для каждой ветки `аудит/01…06`:

- `git log main..аудит/0N --oneline` — каждый коммит соответствует одной
  находке со статусом «исправлено»? Коммит без находки или находка без
  коммита — расхождение, в отчёт;
- на каждой ветке: `npx tsc -b`, `npm run guards`, `npm run check`; если
  трогали бэкенд — четыре прогона. Красное — ветка не сливается, пишешь, что
  именно;
- диф каждого коммита: не вышел ли за 00-ОБЩЕЕ §5 (изменился текст
  интерфейса? поведение? токен? документ с решением?). Вышел — коммит
  помечается «откатить» с причиной;
- слей зелёные ветки по очереди в `аудит/07-сводка` (не в `main`!):
  конфликты решай в пользу более простой правки; после каждого слияния —
  снова `tsc` и `guards`. Итог — одна ветка, которую владелец сливает в
  `main` сам, одной командой, которую ты напишешь в отчёте.

## 3. Собрать `ОТЧЁТ.md`

Структура — строго такая:

1. **Шапка**: дата, хеш `main`, от которого шли; хеш ветки `аудит/07-сводка`;
   числа: находок всего / подтверждено / снято / исправлено / предложено /
   вопросов владельцу; зелёные проверки с числами.
2. **Прочитать за пять минут**: десять самых дорогих находок, по одной фразе
   каждая, с номером.
3. **Находки** по категориям в порядке 00-ОБЩЕЕ §4 (Ломает → Врёт → Опасно →
   Расходится → Мешает → Мусор); внутри — по цене для человека. Каждая — в
   общем формате, со статусом и, если исправлено, хешем.
4. **Исправлено без владельца** — таблица всех коммитов сводной ветки: что,
   чем доказано, что не сломалось.
5. **Регрессы** — что было исправлено по аудитам 02.09/07.09/08.09 и вернулось;
   у каждого — какой караул его бы держал.
6. **Дыры в караулах** — одним списком со всех осей, без повторов, с
   предложенной проверкой в одну строку.
7. **Будущие страницы** — таблица из 05 целиком (это отдельный документ для
   владельца, его не сокращай).
8. **Вопросы владельцу** — один список, пронумерованный, **каждый вопрос —
   да/нет**, при вопросах о виде — картинка «сейчас / предлагаю» рядом.
   Сгруппируй по экранам, чтобы владелец утверждал по одному экрану
   (CLAUDE.md §3а).
9. **Чего аудит не смотрел** — честно, по осям, с причиной.
10. **Как влить**: одна команда для владельца (`git merge --no-ff
    аудит/07-сводка`), что после этого нужно выкатить (фронт — `push main:v1`;
    бэкенд — `ОБНОВИТЬ-СЕРВЕР.md`, есть ли миграции).

## 4. Страница для владельца

По `ОТЧЁТ.md` сделай одну страницу (HTML, самодостаточную, без внешних
зависимостей кроме разрешённых CDN) в `docs/АУДИТ-2026-10/отчёт.html`:
слева оглавление по категориям, справа находки со снимками, у каждого вопроса
владельцу — две картинки рядом и место для ответа. Светлая и тёмная тема, наши
токены из `tokens.css`, телефон. Она же публикуется артефактом — владелец
читает с телефона.

## 5. Когда закончено

- у каждой находки из шести отчётов стоит твой вердикт;
- сводная ветка зелёная по всем проверкам, число проверок записано;
- `ОТЧЁТ.md` и `отчёт.html` лежат в репозитории, в ветке `аудит/07-сводка`;
- последняя строка отчёта — команда для владельца и то, что он увидит после
  неё.
