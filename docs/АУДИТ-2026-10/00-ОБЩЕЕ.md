# 00 · Общее для всех сессий аудита

Это читает каждая сессия перед своим распоряжением. Здесь — закон аудита:
что такое находка, что можно чинить без владельца, как доказывать, куда
писать, чего не делать никогда. Своё распоряжение (`0N-….md`) говорит, ЧТО
смотреть; этот файл — КАК.

---

## 1. Что такое Flamingo и где что лежит

Flamingo — российский продукт для живых онлайн-уроков: преподаватель заводит
урок, отдаёт ссылку, класс входит, идёт урок с видео, звуком, доской и
материалами; после урока — кабинет, журнал, переписка. Модуль SEduM —
внимание ученика на уроке, считается на его устройстве.

Прочитать до начала, в этом порядке:

1. `CLAUDE.md` — правила работы над проектом. Особенно §2 (ограничения не
   выдумываются), §3а (экраны утверждает владелец, по одному), §4 (цвет),
   §5 (токены), §7 (замер вместо мнения), §9 (npm install — только на маке).
2. `docs/FLAMINGO-V1.md` — кто пользователь и путь целиком.
3. `docs/ПРАВИЛА-ДИЗАЙНА.md` — закон экранов. 🔴 Запреты (§8 и прочие
   «нельзя») **не основание** что-то не делать (решение владельца 30.08);
   ремесленная часть действует.
4. `docs/SEDUM-ВНИМАНИЕ.md`, `docs/SEDUM-ИССЛЕДОВАНИЕ.md` — модуль внимания.
5. Решения владельца: `docs/РЕШЕНИЯ-ВЛАДЕЛЬЦА-*.md`, `docs/дизайн/утверждено/`.
   Летопись `docs/старое/РЕШЕНИЯ-ВЛАДЕЛЬЦА-до-28.08.md` — читать, чтобы не
   спорить с решённым; брать оттуда задачи — нельзя.
6. Прошлые аудиты: `docs/АУДИТ-ИНТЕРФЕЙСА-02.09.md`, `-07.09.md`,
   `docs/ОСМОТР-КАБИНЕТА-08.09.md`, `docs/ОСМОТР-КОМНАТЫ-08.09.md`,
   `docs/UX-РЕВИЗИЯ-ЛИСТОВ.md`.

Карта кода:

| Что | Где |

## 2. Три машины и что на какой можно

- **Мак владельца** — здесь живёт репозиторий и здесь ты работаешь. `git`
  обычный. `npm run dev`, `npm run build`, `npm run check`, `npm run guards`,
  `npx tsc -b`, `npx oxlint` — всё работает.
- **Облачный контейнер** (если ты в нём) — боевой сайт `flamingo.plus` и
  `api.flamingo.plus` **недоступны**, вместо страницы приходит подделка. Замеры
  боевого из облака — мусор. Playwright есть.
- **Боевой сервер `root@82.147.71.204`** — **не трогать**. Никаких ssh, никаких
  команд «для владельца, чтобы он выполнил». Всё, что ты хочешь узнать о боевом,
  — вопрос в отчёт.

🔴 Запрещено без исключений:

- `npm install`, `npm ci`, `npm update`, `npx <что-то, чего нет в node_modules>`,
  правка `package.json`/`package-lock.json`/`requirements.txt`. Нужен
  инструмент — напиши в отчёт, какой и зачем. (`CLAUDE.md` §9.)
- `git push`, любые действия с ветками `main` и `v1`, `git rebase`, `git reset
  --hard`, удаление чужих веток.
- Секреты: `.env` не читать, не печатать, не копировать, не коммитить. Ключи,
  пароли, токены в отчёте не появляются, даже частично.
- Удалять что-либо вне git (папки `УДАЛИТЬ-*`, `_to_delete/`, `сборка/`,
  `node_modules`) — нельзя. Можно только перечислить в отчёте.
- Менять то, что видит человек: текст, вёрстку, цвет, порядок, поведение,
  адреса API, схему базы, токены в `tokens.css`, тексты писем. Это — решение
  владельца, по одному пункту (`CLAUDE.md` §3а).

## 3. Как работать: ветка, коммиты, отчёт

1. Создай свою ветку от текущего `main`: `git switch -c аудит/0N-<область>`.
   Все коммиты — туда. Параллельные сессии не мешают друг другу, потому что
   каждая правит только то, что названо в её распоряжении, и пишет только свой
   файл отчёта.
2. Отчёт — `docs/АУДИТ-2026-10/отчёты/0N-<область>.md`. Заводи его в первые
   десять минут и дописывай по ходу: оборванная сессия должна оставить после
   себя отчёт, а не память.
3. Одна починка — один коммит. Сообщение начинается с `Аудит 0N:`, называет
   находку по номеру и говорит, чем доказано, что ничего не сломалось.
   Коммит заканчивается строками:
   ```
   Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>
   Claude-Session: <адрес этой сессии>
   ```
4. Перед каждым коммитом зелёные: `npx tsc -b`, `npm run guards`, а если
   трогал бэкенд — все четыре `backend/*/прогон.py` (`.venv/bin/python
   study/прогон.py` и т. д.). Красный караул — не повод его править; это повод
   не делать починку.
5. В конце — `npm run check` (включает `vite build` и `сборка-check`): сборка
   обязана собираться.

## 4. Что считается находкой

Находка — это **нарушение названного правила** или **измеренный дефект**.
У каждой находки есть:

- **Номер** `0N-<порядковый>`, например `03-017`.
- **Где**: файл и строка, экран и кадр, или запрос и ответ.
- **Что не так** — одной фразой.
- **Чем доказано**: число, снимок, вывод команды, строка кода. Не «выглядит».
- **На что опирается**: правило (`ПРАВИЛА §6.1`), решение владельца (файл,
  дата), лист (`Комната урока.dc.html`), или честное «правила нет, предлагаю».
- **Что ломается у живого человека**: не «неаккуратно», а «преподаватель на
  1280×800 не видит „Позвать“ и не может начать урок».
- **Как чинить** и **цена**: S (до часа), M (полдня), L (день и больше).
- **Статус**: `исправлено <хеш коммита>` · `предложено` · `вопрос владельцу`.

Порядок находок в отчёте — по цене для человека, а не по порядку обнаружения:

1. **Ломает** — человек не может сделать то, зачем пришёл.
2. **Врёт** — интерфейс или документ говорит не то, что есть.
3. **Опасно** — утечка, дыра, потеря данных, нарушение закона о данных.
4. **Расходится с утверждённым** — продукт ушёл от листа, правила или решения.
5. **Мешает** — можно, но неудобно; медленно; дорого в поддержке.
6. **Мусор** — мёртвое, лишнее, устаревшее; никому не вредит, но врёт о
   размере и состоянии проекта.

**Не находка:** вкусовщина без правила; «я бы сделал иначе»; спор с решением
владельца (найди решение прежде, чем спорить); то, что уже ловит караул;
предложение сменить стек; кириллица в именах.

🔴 **Не рассуждай там, где можно измерить.** Размер, цвет, время, обрезка,
количество — числом, снятым командой или прибором. За прошлые недели трижды
уверенный вывод по одному наблюдению оказывался неверным.

🔴 **Прежде чем назвать что-то мёртвым — докажи тремя способами:** grep по
`src` и `scripts` (включая стенд `Стенд.tsx` и караулы — они импортируют то,
что продукту не нужно), `npx tsc -b` после удаления, `npm run guards` после
удаления. Караулы читают исходники текстом и требуют присутствия строк, которых
продукт «не использует».

## 5. Что чинить самому (бесспорное) — и что только в отчёт

**Чинить самому, коммит на каждую, без вопросов:**

- неиспользуемые импорты, переменные, параметры, экспорты, типы — после
  тройного доказательства из §4;
- файлы, на которые никто не ссылается (ни код, ни стенд, ни караул, ни
  `index.html`, ни документы) — удалять через `git rm`;
- CSS-классы, которых нет ни в одном `.tsx`/`.ts` (проверять и составные
  имена: `s[`${…}`]`, `data-`-атрибуты, селекторы по атрибутам);
- комментарии и документация, которые **фактически неверны о коде**
  («здесь 44 экрана», а их 100; «функция X делает Y», а она делает Z) —
  поправить число или фразу. Комментарии о решениях владельца, с датами, —
  **не трогать**, даже если кажутся устаревшими: это летопись;
- дублирующийся код, который **байт в байт** одинаков и собирается в одну
  функцию без изменения поведения — только если караулы и прогоны после этого
  зелёные и диф читается за минуту;
- `__pycache__`, `.pyc`, `.DS_Store`, пустые папки, попавшие в git —
  `git rm --cached` и строка в `.gitignore`, если её нет;
- опечатки в комментариях и в документах (не в тексте интерфейса!).

**Только в отчёт, с предложением, никаких правок:**

- всё, что видит человек: слова, вёрстка, цвет, состояния, порядок, анимации;
- поведение: логика, условия, сроки, пороги, формулы (включая движок внимания);
- API, схема базы, миграции, настройки, `.env.example`;
- зависимости и версии;
- архитектурные перестановки («вынести в хук», «разбить файл») — даже
  бесспорно полезные: это M/L и решение владельца;
- документы с решениями владельца, `ПРАВИЛА-ДИЗАЙНА.md`, листы дизайна;
- всё, в чём есть хоть одно сомнение. Сомнение = отчёт.

Если починка бесспорна по букве, но тянет за собой что-то ещё — она не
бесспорна. В отчёт.

## 6. Как получить продукт под замер

На маке: `cd frontend && npm run dev` → `http://127.0.0.1:5180`. Стенд:
`/стенд?э=<имя>&чисто=1`; список имён — реестр в `Стенд.tsx` (сейчас ~100
экранов и частей). Бэкенд локально:

```
cd backend
DB_PATH=/tmp/аудит.sqlite3 SECRET_KEY=проба DEBUG=1 \
  CORS_ALLOWED_ORIGINS=http://127.0.0.1:5180 \
  .venv/bin/python manage.py migrate
DB_PATH=/tmp/аудит.sqlite3 SECRET_KEY=проба DEBUG=1 \
  CORS_ALLOWED_ORIGINS=http://127.0.0.1:5180 \
  .venv/bin/python manage.py runserver 127.0.0.1:8000
cd frontend && VITE_AUTH_URL=http://127.0.0.1:8000 npm run dev
```

Без `LIVEKIT_*` комната честно говорит «Эфир не поднялся» — так и должно быть;
эфир вживую проверяет владелец. Пробные учётные записи заводи на домене
`example.test`, пароли вида «четыре слова стенда …»; боевых адресов и людей не
трогать.

Кадры: **1280×800** и **1512×944** обязательные; телефон 390×844 и 360×740;
плюс 1024×620 и 1728×1080. Темы: светлая, тёмная (`data-theme`), детский режим
`data-mode="kids"`. Роли: гость, ученик, преподаватель. Сервер молчит.

Браузер для замеров — Playwright (Chromium) с мака. Снимки класть в
`docs/АУДИТ-2026-10/отчёты/снимки/0N-…png`, не больше 300 КБ каждый.

## 7. Когда сессия закончена

- каждый пункт распоряжения либо пройден, либо в отчёте написано «не смотрел,
  потому что …» — пробел словами, а не молчанием;
- отчёт содержит три хвоста: **регрессы** (было исправлено — вернулось),
  **дыры в караулах** (что стоило бы ловить машиной и как), **вопросы
  владельцу** (где правила нет и решение за ним) — каждый вопрос так, чтобы
  ответом было «да» или «нет»;
- последняя строка отчёта: `tsc`, `guards`, `check`, прогоны — что зелёное, с
  числами проверок, и хеш последнего коммита ветки.
