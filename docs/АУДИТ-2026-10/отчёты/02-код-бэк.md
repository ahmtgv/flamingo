## 2. Находки

Порядок — по цене для человека (00-ОБЩЕЕ §4). Статус «предложено» = правка
не моя по §5; «вопрос владельцу» — решение за ним.

### Опасно

#### 02-001 · Ключ подписи куки по умолчанию известен каждому, и ничто не мешает боевому с ним стартовать
- **Где:** `config/settings.py:23` — `SECRET_KEY = os.getenv("SECRET_KEY", "") or "небоевой-ключ-только-для-разработки"`; `DEBUG` там же, по умолчанию `"1"`.
- **Что не так:** если в боевом `.env` строка `SECRET_KEY=` пуста или отсутствует (пустая строка в `.env.example` — ровно такая), сервер молча подписывает куки строкой из репозитория. Любой, кто знает `id` человека, собирает себе его куку.
- **Чем доказано:** на своей базе без `SECRET_KEY`:
  `signing.dumps({"id": T1}, salt="flamingo.session", key="небоевой-ключ-только-для-разработки")` → `GET /api/auth/me` → `200 {"person": {"id": …, "name": "Учитель Один", "role": "teacher"}}`. `id` преподавателя ученик видит в `/api/study/teachers` и `/api/study/talks`, `id` ученика преподаватель — в журнале.
- **На что опирается:** `docs/СВОЙ-СЕРВЕР-УЧЁТКИ.md` шаг 4 велит сгенерировать ключ и поставить `DEBUG=0` — то есть правильно настроенный боевой защищён. Но код этого не требует: ошибка в одной строке `.env` = полный вход под любым человеком, без единого слова в журнале.
- **Что ломается:** при одной опечатке в `.env` чужой читает переписку, журнал и пособия любого человека, и кабинет исследования, если знает почту владельца.
- **Как чинить (S):** в `settings.py` после чтения — `if not DEBUG and not os.getenv("SECRET_KEY"): raise ImproperlyConfigured("SECRET_KEY пуст…")`; то же для `DEBUG`: в `.env.example` поставить `DEBUG=0` с комментарием «на маке — 1». `people/прогон` уже проверяет, что небоевой ключ «виден как небоевой» — проверка на старте закрыла бы дыру, а не только подсвечивала.
- **Статус:** предложено (настройки — §5) + **В-1**.

#### 02-002 · Любой запирает чужой вход на 20 минут пятью попытками
- **Где:** `people/guard.py:35-47` (`missed(email, ip)`), `people/views.py` → `login` считает по почте и адресу.
- **Что не так:** счёт по почте запирает почту для всех адресов. Пять неверных паролей от злоумышленника — и сам человек не входит двадцать минут; повторять можно бесконечно. Докстринг `Tries` в `people/models.py:48-57` утверждает: «Только по почте — и любой желающий запирает чужой вход… Вместе они закрывают оба случая» — **второе неверно о коде**: случай «запереть чужого» закрыт не стал.
- **Чем доказано:** 5 × `POST /api/auth/login {email: t1@…, password: "неверный"}` с `REMOTE_ADDR=10.0.0.66` → далее верный пароль с `10.0.0.7` → `429 «Слишком много попыток. Попробуйте через 20 мин…»`.
- **На что опирается:** решение владельца 31.08 «пять попыток и двадцать минут отдыха» — поэтому не правка.
- **Что ломается:** ученик за минуту до урока не может войти, потому что одноклассник пошутил; преподаватель — тоже.
- **Как чинить (M):** считать по почте мягче (например, замедление/капча или запирание только для пары почта+адрес, а по одной почте — лишь после 50 попыток), либо снимать запрет по почте успешной сменой пароля (уже есть) и ссылкой «это не я». Комментарий в `Tries` поправить после решения.
- **Статус:** вопрос владельцу **В-2**.

#### 02-003 · Регистрация без ограничения попыток при дорогом хеше
- **Где:** `people/views.py` `register` — нет `guard.locked_for/missed`; `HASHER = PasswordHasher()` (argon2id, 3 прохода, 64 МБ, 4 потока).
- **Чем доказано:** 20 регистраций подряд с разных почт → 20 × 200; одна регистрация — 130 мс процессора и 64 МБ памяти (замер на своей базе).
- **Что ломается:** посторонний скриптом заводит тысячи пустых учётных записей и одновременно съедает процессор: при четырёх рабочих gunicorn ~30 запросов в секунду кладут вход всем. Данные не утекают — это доступность.
- **Как чинить (S):** тот же `guard` по адресу: `locked_for(f"рег:{ip}")` + `missed` после каждой регистрации, порог побольше (например 20 в час).
- **Статус:** предложено (поведение).

#### 02-004 (условно) · Адрес из `X-Forwarded-For`/`CF-Connecting-IP` берётся на веру
- **Где:** `people/guard.py:17-21`.
- **Чем доказано:** 8 неверных входов с одного `REMOTE_ADDR` и разными `X-Forwarded-For` → все `401`, запрета нет; те же 8 без заголовка → с шестого `429`. Счёт по адресу обходится заголовком от клиента.
- **На что опирается:** правила нет. Опасно, только если до gunicorn/Caddy можно дойти не через Cloudflare, или Caddy пропускает чужой `CF-Connecting-IP`. Из облака не проверить.
- **Как чинить (S):** читать только тот заголовок, который ставит наш обратный прокси (у Caddy — `X-Forwarded-For` первым значением, если `trusted_proxies` настроен), остальные игнорировать.
- **Статус:** вопрос владельцу **В-3**.

### Врёт

#### 02-005 · Журнал считает «прошёл» по UTC, а не по поясу урока
- **Где:** `study/views.py:319,336` — `сейчас = timezone.localtime()` (TIME_ZONE=UTC) и `(l.on, l.at) <= (сейчас.date(), сейчас.time())`, при том что `l.on/l.at` — настенные часы в `l.tz`.
- **Чем доказано:** урок `tz=Europe/Moscow` на 13:21 при 14:21 по Москве (11:21 UTC) → `"прошёл": false`.
- **Что ломается:** у преподавателя из Москвы последний урок три часа «ещё не прошёл», у Владивостока — десять; «прошёл» на листе журнала и подсветка на кадре врут.
- **Как чинить (S):** `now_в_поясе = timezone.now().astimezone(ZoneInfo(l.tz)) if l.tz else timezone.now()`; пусто в `tz` — считать как сейчас (честное «не знаем»). Проверка в прогоне — одна строка.
- **Статус:** предложено (поведение).

#### 02-006 · `GET /api/room/token` отвечает 405 без слов
- **Где:** `room/views.py:44` `@require_POST` — Django отдаёт пустой `405`. Все остальные пути бэкенда отвечают `{"error": "Этот путь отвечает только на POST."}`.
- **Чем доказано:** `GET /api/room/token` → `405 b''`. Прогон `room` проверяет только код.
- **На что опирается:** ПРАВИЛА 6.4 (отказ словами) — распоряжение велит применять и к API.
- **Как чинить (S):** снять `require_POST`, проверить метод вручную как в соседних файлах. **Статус:** предложено.

#### 02-007 · Файл пособия скачивается под случайным именем
- **Где:** `study/views.py:287` `FileResponse(open(полный, "rb"), content_type=…)` без `filename=`.
- **Чем доказано:** заголовки ответа: `Content-Disposition: inline; filename="218964a2…a5b5.pdf"` — Django взял имя файла с диска (uuid), а человеческое имя лежит в `m.name`.
- **Что ломается:** ученик сохраняет «план урока.pdf», а получает `218964a2b2a842639b31a15aea02a5b5.pdf`.
- **Как чинить (S):** `FileResponse(…, filename=m.name)` (Django сам кодирует кириллицу через `filename*`). **Статус:** предложено.

#### 02-011 · Отметка посещения ставится любому вошедшему, не только ученикам

#### 02-014 · Таблица `tries` растёт без уборки

### `@csrf_exempt`: где и почему безопасно
Стоит на всех изменяющих путях (`people/views.py`, `study/views.py`, `room/views.py`,
`science/views.py`, `science/кабинет.py`). Держится на трёх вещах: кука
`SameSite=Lax` (кросс-сайтовый POST её не несёт; `flamingo.plus` и `api.` — один
сайт), JSON-тело (предзапрос CORS, чужой источник не в списке — замер: `OPTIONS` с
`Origin: http://evil.test` → без `Access-Control-*`), и для `science/v/*` — куки
нет вовсе. Исключение по форме: `materials` POST принимает `multipart` — такой
запрос с чужого сайта браузер отправит без предзапроса, но без куки (Lax) → 401.
Единственный лаз — поддомен `*.flamingo.plus` под чужим управлением; сейчас их нет.

### CORS и парные `OPTIONS`
Предзапрос идёт на каждый **новый** URL (у уроков и разговоров id в адресе) с
`credentials: include` и `Content-Type: application/json`; `Access-Control-Max-Age:
86400` стоит, но Chromium кэширует не дольше 2 часов и по адресу. Пары в логе
стенда — норма, не дефект.

## 5. Правильность — остальное

- **Пояса.** `TIME_ZONE=UTC`, `USE_TZ=True`. Наивных сравнений с aware нет;
  единственная ошибка смысла — 02-005. `common/пояс.py` при пустой базе поясов
  падает на импорте `RuntimeError` словами — громко, как задумано (ветка
  `ZoneInfoNotFoundError` недостижима: `available_timezones()` не бросает, а
  отдаёт пустоту — её ловит вторая проверка; первая — мёртвая, но безвредная).
- **N+1 при 30 учениках × 20 уроков** (`CaptureQueriesContext`): журнал — 5
  запросов, `talks` (60 сообщений) — 4, `lessons` учителя — 3, ученика — 4,
  `talk/<кто>` — 3. N+1 нет.
- **Тексты отказов.** Все `_no/_bad` в `people`, `study`, `room`, `кабинет`
  говорят словами, что не так и что делать. В `science/views.py` коротко («Не тот
  метод.», «Такой проверки нет.») — допустимо, но суше соседей. Пустой 405 — 02-006.
- **Загрузки.** Список разрешённых расширений (без `.svg`/`.html` — проверено:
  `.html` → 400 словами; `.PNG` заглавными — принят), имя на диске — uuid
  (`../../etc/passwd.txt` → лёг как `materials/<урок>/<hex>.txt`, в базе имя
  `passwd.txt`), двойная проверка размера (заголовок и факт). Отдаёт Django
  (`FileResponse`) с `nosniff`, `CSP sandbox; default-src 'none'`, `Cache-Control:
  private` — верно; `Content-Disposition` — 02-007. На боевом перед gunicorn Caddy
  (CLAUDE.md §8, уточнение 25.10): лимит тела там — вопрос 06/владельцу.
- **Пароли.** argon2id (`argon2-cffi` по умолчанию: t=3, m=64 МБ, p=4),
  перехеширование старых `pbkdf2$` при входе, одинаковый 401 и пустой `verify` для
  незнакомой почты (время выравнено). Сброс: ключ 32 байта, в базе SHA-256,
  срок 1 ч, одноразовый, остальные ключи гасятся, запрет снимается. Проверено
  прогоном `people` (63).
- **LiveKit.** `canUpdateOwnMetadata: False` стоит явно; `metadata={"ведёт": true}`
  только хозяину (`lesson.teacher_id == person.id`); срок токена 6 ч (`ttl_hours`);
  без любой из трёх `LIVEKIT_*` — `503` словами, `healthz` → `livekit:false`
  (прогон `room`). 6 часов — больше любого урока (480 мин максимум), но токен
  гостя переживает урок на 2 часа; правила нет.
- **Почта.** Отправитель только `settings.DEFAULT_FROM_EMAIL`;
  `hello@whiteobservatory.com` в `backend/*.py` не встречается (grep), есть лишь
  запрет в `.env.example` и в распоряжении.
- **Заголовки.** Django сам лишнего не добавляет (`Vary: origin` от CORS);
  `Server:` ставят gunicorn и Caddy — из облака не замерить (**В-9**).
- **`common/браузер.py`, `снимки.py`, `хаб_снимки`.** Playwright импортируется

  обход продолжается витринами. В боевой процесс gunicorn ничего не тянет: модуль
  `браузер` импортируется только командой. Установлен ли хром на сервере —
  вопрос владельцу, из облака не видно (**В-10**).

- **В-3.** `api.flamingo.plus` доступен только через Cloudflare, и Caddy не пропускает чужой `CF-Connecting-IP`/`X-Forwarded-For`? Если нет — чинить 02-004.

- **В-5.** Отметка посещения нужна только ученикам по `Bond`, или любому вошедшему по ссылке? (02-011)
- **В-6.** На боевом `EMAIL_HOST` задан? Если был пуст хоть день — в journald лежат почты и живые (уже протухшие) ссылки сброса; стоит ли их вычистить и запретить печатать ссылку вне `DEBUG`?
- **В-7.** Обновлять ли пины (`argon2-cffi`, `PyJWT`, `django-cors-headers`, `python-dotenv`) до свежих минорных — руками владельца на маке и сервере?
