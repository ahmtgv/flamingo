# Аудит 04 · UX: пути насквозь, честность, слова, тупики

Сессия шла в облаке (`ОБЛАКО.md`): фронт `127.0.0.1:5199` (vite dev), бэкенд
`127.0.0.1:8000`, чистая база, `EMAIL_HOST` пуст (ссылки брались из лога сервера),
эфира нет. Playwright (Chromium, headless), отдельный persistent-профиль на роль:
`учитель`, `ученик`, `гость`, `доброволец`, `клавиатура`, телефонные. Правок в

00-ОБЩЕЕ §5 — комментарий в `Room.tsx`, см. 04-020 — отдан в отчёт, файл чужой).

Учётные записи стенда: `uchitel@example.test` (Наталья Ким, преподаватель),
`uchenik@example.test` (Аня Соколова, ученик), `kb@example.test` (Клавиатурный
Учитель). Урок «Алгебра — квадратные уравнения», комната `ycrs-kybs-fwwh`.

Снимки: `снимки/04-*.png`, 141 шт., все ≤ 300 КБ (ужаты квантованием, цвета
в них слегка упрощены). Скрипты прохода — в scratchpad сессии, в репозиторий не
клались.

## 0. Ограничения стенда, из-за которых часть не измерена

| Что | Почему | Как это отражено |
|---|---|---|
| Шрифты Manrope и JetBrains Mono не грузятся (vite отвечает 403 на `/@fs/…/бенч/node_modules/@fontsource-variable/…`) | `node_modules` стенда — ссылка за пределы `fs.allow` | все замеры ширины текста (обрезки) помечены «с запасным шрифтом, перепроверить на маке» |
| `localStorage` не переживает перезапуск headless-профиля (проверено: `setItem` → закрыть → открыть → `null`) | особенность headless-Chromium; куки при этом живут | память устройства в исследовании («Кто сейчас проходит?»), запомненное имя гостя и тема между запусками — **не смотрел**; внутри одной сессии проверено |
| `SCIENCE_OWNERS` на стенде пуст, общий бэкенд перезапускать нельзя | — | кабинет исследования владельцем — **не смотрел**; смотрел только два отказа (гость, не-владелец) |
| Проверка исследования после «Начать запись» | модель лица загрузилась (`XNNPACK delegate`), но страница в headless перестаёт отвечать на нажатия (клик по галочке «Слышу сигнал» не доходит за 30 с) | путь добровольца пройден до экрана «Подготовка» включительно; запись, итог, «как вы» второй раз — **не смотрел** |
| Темы (тёмная, kids), 1512 и прочие кадры | область 03; здесь — только 1280×800 и телефоны | — |
| VoiceOver | нет мака | заменён клавиатурой и axe-core (раздел 5) |
| Время до первого экрана | dev-сервер vite, цифры не о продукте | не приводятся |

## 1. Находки

Нумерация `04-NNN`, порядок — по цене для человека (00-ОБЩЕЕ §4). Статус у всех

### Ломает

**04-001 · Преподаватель при молчащем сервере занятий получает в своей комнате экран ученика — без единого слова.**
- Где: `frontend/src/screens/Room.tsx:115-130` (`пособияКомнаты(code)…catch(() => undefined)`), снимок `04-частичный-06-комната-учитель-без-сервера-занятий.png`.
- Чем доказано: `page.route('…/api/study/**' → abort)`, вход учителем по `/r/ycrs-kybs-fwwh`: шапка «Урок по ссылке · связи нет», вместо полки — кнопка «Доска», пульт без «Скопировать ссылку», выход подписан «Выйти из комнаты». Ни слова о том, что роль не получена и почему.
- На что опирается: ПРАВИЛА 6.4 (отказ называет причину), 6.5а (частичный отказ называет, что не работает). Сервер занятий и сервер учётных записей — один Django, но запросы разные, и `whoAmI` прошёл, а `rooms/<код>` — нет (так же будет при 5xx только у `study`).
- Что ломается: преподаватель открывает свой урок, не может показать ни доску классу, ни материалы, и думает, что это он что-то нажал не так. В кабинете про это сказано («ведущего назначает сервер»), в комнате — нет.
- Как чинить: в `catch` ставить состояние «сервер занятий не ответил — вы вошли без прав ведущего; полка и материалы появятся после повторного входа» и давать «Спросить ещё раз». Цена S.

**04-002 · Гость по правильной по виду ссылке на несуществующую комнату проходит весь путь и упирается в «Эфир не поднялся».**
- Где: `App.tsx:458` (`Enter` рисуется по виду кода, сервер не спрашивается), `room/Stage.tsx:132-144`, снимок `04-гость-07-комната-которой-нет.png`.
- Чем доказано: `/r/zzzz-zzzz-zzzz` → «Вас ждут в комнате» → имя «Петя» → «Войти в комнату» → через 6 с карточка «Эфир не поднялся», красным «Нет такой комнаты. Проверьте ссылку — возможно, урок уже сняли», ниже «Написанное на доске цело…» и кнопка «Поднять эфир заново».
- На что опирается: ПРАВИЛА 6.4 (одно действие, которое помогает), 6.5в (состояние принадлежит операции: «нет комнаты» — не отказ эфира).
- Что ломается: ученик по ссылке на снятый урок читает «вас ждут», называет себя, ждёт, затем — про эфир и доску, и кнопка «Поднять заново» ничего не поднимет. Выход — только знак в шапке.
- Как чинить: ответ `rooms/<код>` → 404 показывать до формы имени (экран «такой комнаты нет» с «Ко входу/На главную»), а в комнате для 404 — своя карточка без «доска цела» и без «поднять эфир». Цена M (проверка кода до входа — поведение, решение владельца).

**04-003 · Два тупика без выхода: `/наука/<мусор>` и `/наука/кабинет` для вошедшего не-владельца.**
- Где: `наука/экраны.tsx` (`НетСсылки`), `наука/Кабинет.tsx` (ветка 403); снимки `04-гость-битая-_наука_мусор.png`, `04-наука-кабинет-учитель.png`.
- Чем доказано: `document.querySelectorAll('button,a')` → `[]` на обоих экранах; знак `flamingo.` не нажимается.
- На что опирается: CLAUDE.md §3 п.3 («из экрана есть выход, тупиков нет»).
- Что ломается: человек, открывший ссылку с опечаткой, остаётся на странице без единой двери; преподаватель, случайно попавший в `/наука/кабинет`, — тоже.
- Как чинить: знак → «На главную» (как в `Invite`) или кнопка «На главную». Цена S.

### Врёт

**04-004 · «Урок по ссылке при этом работает» — неправда, когда сервер молчит.**
- Где: `lib/auth.ts:61` (текст отказа входа «Сервер Flamingo не отвечает. Урок по ссылке при этом работает.»), `ui/Wait.tsx:48` («комната живёт отдельно от сервера»); снимки `04-гость-молчит-вход-нажал.png`, `04-гость-молчит-комната.png`.
- Чем доказано: при `route(…:8000/** → abort)` вход говорит «урок по ссылке работает», а комната в той же сессии — «Эфир не поднялся · Сервер Flamingo не отвечает. Урок и ссылка на месте — попробуйте войти ещё раз через минуту». Билет в эфир выдаёт тот же сервер (`backend/room/urls.py: token`).
- На что опирается: ПРАВИЛА 6.4; CLAUDE.md §7.
- Что ломается: ученик, не сумевший войти, идёт «по ссылке» и получает второй отказ; преподаватель рассылает ссылку, веря, что урок пройдёт без сервера.
- Как чинить: убрать обещание из двух текстов (вход/регистрация и `Молчание`), оставив «попробуйте через минуту». Цена S. Текст — решение владельца.

**04-005 · Чат занятия: «Пока учётных записей нет, переписка живёт только во время урока» — учётные записи есть с куска 3.**
- Где: `room/Chat.tsx:121`, снимок `04-учитель-19-чат-без-эфира.png`.
- Чем доказано: текст виден вошедшему преподавателю с именем в раме.
- Опирается: ПРАВИЛА 6.2 (пусто говорит правду о том, что здесь будет).
- Что ломается: вошедший читает, что учётных записей «нет», и не понимает, зачем регистрировался.
- Как чинить: «Чат живёт, пока идёт урок: все вышли — чат исчез. Вопросы вне урока — в переписке из кабинета». Цена S.

**04-006 · Кабинет преподавателя при молчащем сервере занятий заголовком говорит «Занятий на сегодня нет» и «занятий нет» — при пяти уроках на сегодня.**
- Где: `screens/Cabinet.tsx:413-422, 448`; `lib/study.ts` (`читатьУроки` при молчании отдаёт запас из браузера, `гдеЛежат() === 'браузер'`); снимок `04-частичный-01-кабинет-без-занятий.png`.
- Чем доказано: `route('/api/study/**' → abort)` при живом `/api/auth/me`: слева «Занятий на сегодня нет», в календаре «занятий нет», ни одной точки; в теле абзаца при этом сказано, что сервер не отвечает.
- Опирается: ПРАВИЛА 6.3/6.4; аудит 07.09, находки 15–16 («сервер отказал — не „занятий нет“») — закрыты для **отказа** (ответ с ошибкой), но не для **молчания** (сеть/5xx): оно падает в ветку «браузер» и рисует пустоту заголовком. Частичный регресс.
- Что ломается: репетитор с полным днём читает крупно «занятий нет», мелко — почему.
- Как чинить: при `дом === 'браузер'` и пустом запасе показывать состояние отказа («Расписание не открылось… Посмотреть ещё раз»), а не «пусто». Цена S–M.

**04-007 · `/урок/<несуществующий id>` и `/урок/<id>` при молчащем сервере молча превращаются в форму «Создать урок».**
- Где: `screens/NewLesson.tsx:85-100` (`читатьУроки().then(все.find…)` — не нашли → ничего; `catch(() => undefined)`); снимки `04-учитель-32-урок-мусор.png`, `04-частичный-05-урок.png`.
- Чем доказано: адрес `/урок/мусор` → крошка «Создать урок», пустая форма, «Создать урок»; то же для настоящего id при обрыве `study`.
- Опирается: ПРАВИЛА 6.4; CLAUDE.md §3а (один экран — два состояния, но «не нашли» — третье).
- Что ломается: преподаватель по старой закладке/при сбое видит пустую форму, решает, что урок пропал, и заводит второй — класс получает вторую ссылку.
- Как чинить: состояния «урок не найден — возможно, убран» и «сервер не ответил — попробовать ещё раз» вместо пустой формы. Цена S.

**04-008 · Имя вкладки врёт на четырёх адресах.**

**04-009 · Регресс 10.10, частичный: вошедшему по прямой ссылке `/r/<код>` показывается форма «Назовитесь» на всё время ответа `/api/auth/me`.**
- Где: `App.tsx:445-469` — `Wait` стоит только в ветке `!code`; с кодом до `узнали` рисуется `Enter`.
- Чем доказано: без задержки форма видна ~300 мс (замер по 100 мс: 100 — «Смотрим, кто вошёл» (Suspense), 300 — «Вас ждут в комнате / Назовитесь», поле имени есть, 600 — комната); при задержке `/me` 1,5 с — форма видна с 1015 по 4283 мс. Снимок состояния — `04-учитель-44-прямая-ссылка-вошедшим.png` (уже комната), промежуточный кадр в тексте выше.

- Что ломается: на школьном 3G (400 мс+) вошедший ученик видит «назовитесь», начинает печатать, экран сменяется комнатой.
- Как чинить: при `code && !узнали` показывать `Wait` (как для `!code`); гостю без куки ответ приходит так же быстро. Цена S.

## 7. Доступность (клавиатура + axe)

- С клавиатуры пройдено целиком: титул → `Enter` на «Завести» → регистрация (Tab: почта → имя → роли → пароль → кнопка) → кабинет → «Создать урок» → название + `Enter` создаёт → Tab до «Войти в комнату» → комната → язычок пульта → 5 кнопок → «Завершить урок». Порядок Tab логичен; в комнате язычок первым, пульт раскрывается `Enter`, кнопки пульта в обходе только раскрытыми.
- Фокус после перехода на новый экран — `body` (регистрация → кабинет; `Enter` на титуле → регистрация): читалка не узнает, что экран сменился. Кандидат: фокус на `h1`/первое поле (у «Создать урок» и «Вас ждут» `autoFocus` есть).
- Кольцо фокуса видно: `box-shadow 0 0 0 3px rgba(47,138,86,.9)` на «Войти» (снимок `04-клавиатура-фокус-войти.png`).
- `Esc`: закрывает окно «Добавить ученика» (фокус возвращается), меню «Методички»; **не закрывает** переписку и чат (04-027).

## 9. Дыры в караулах

1. **Имя вкладки от адреса, а не от экрана** — караул не поймает; прибор: на каждом маршруте стенда сверять `document.title` с `h1`/крошкой.
2. **Обещания текста** («урок по ссылке работает», «учётных записей нет») — машиной не поймать; но список обещаний (§5) можно держать в `docs/` и перечитывать при каждом изменении `backend/`.
3. **`catch(() => undefined)` на запросах, от которых зависит экран** (`Room.tsx:128`, `NewLesson.tsx:98`) — караул по исходникам: `.catch(() => undefined)` разрешён только с комментарием «почему молчим».
4. **Тупик без выхода** — прибор по стенду: на каждом экране хотя бы один `button`/`a`, ведущий прочь (или знак с `onGo`).
5. **`Esc` у поверхностей** — прибор: у каждого `[role=dialog]`/`aside` после `Escape` элемента нет и фокус не `body`.
6. **`Suspense`-ожидание с чужим словом** — стенд: `Wait` без `say` только там, где спрашивают `/me`.
