# ПРАВИЛА ЭКРАННОЙ СИСТЕМЫ

Выведены из восьми собранных листов. Сформулированы так, чтобы по ним можно было проверить
следующий экран прибором, а не глазом. Значения — только из `tokens.css`.

---

## 1. Кадр и прокрутка

| # | Правило | Проверка |
|---|---|---|
| 1.1 | Рабочие кадры — 1280×800 и 1512×944. Оба обязательны, оба снимаются | переключатель кадра на каждом листе |
| 1.2 | Страница не прокручивается никогда | `scrollHeight − innerHeight = 0` |
| 1.3 | Прокручиваемых областей на экране — **не больше двух** | подсчёт элементов с `overflow: auto`, у которых `scrollHeight > clientHeight` |
| 1.4 | Дорога назад — левый верхний угол, во всех четырёх состояниях | наличие кнопки возврата в кадре |

| 3.2 | Рамка карточки | 1 px `--color-border`. Сильная рамка — только у выбранного элемента |
| 3.3 | Верхние кромки карточек одного ряда совпадают | разброс ≤ 2 px |
| 3.4 | Колонки кабинета | 1.05 / 1.2 / 0.85 fr — работа слева, календарь в середине, показатели справа |

| 3.7 | Плитка участника | минимум 104 × 65; при 20 участниках решётка 5 × 4; ниже 56 px по высоте — лишние уходят в подпись «ещё N» |

| 3.10 | **На холсте не остаётся ничего плавающего.** Управление доской живёт в раме — панель инструментов и пульт; холст остаётся холстом. Плавающая плашка отнимает у холста и место, и работу: строка настроек шириной 510–707 px в центре холста оставляла доске 639 px из 1280, а в продукте нажатия до доски не доходили вовсе — под курсором оказывались карточка занятия и панель инструментов. Один диагноз с двух сторон (решение владельца §62) | прибор `textUnderLayer` + прибор 19: щелчок по холсту меняет холст |

## 4. Типографика

| # | Правило |
|---|---|
| 4.1 | Заголовок страницы — один на экран: `--text-h1` (32), вес 600 |
| 4.2 | Заголовок карточки — **не второй титул**: моно 12 px, вразрядку `.08em`, прописными, `--color-text-tertiary` |
| 4.3 | Основной текст `--text-body` (17), пояснения `--text-small` (14), подписи `--text-caption` (13). Ниже 13 px в продукте нет |
| 4.3а | **Размер берётся токеном, а не числом.** Голый `10px` / `11px` в шрифте проверяется только глазами (`rawValues` смотрит отступы и цвет) и вдвойне врёт в `data-mode="kids"`: цель нажатия растёт, а подпись под ней — нет. На телефоне это закрыто полностью: всё, включая полку вкладок и статусные строки, — не мельче `--text-caption` |
| 4.4 | Моно — только числа, время, метки, счётчики и служебные подписи. Кнопки и заголовки — SF/Inter |
| 4.5 | Крупное число (метрика) — `--text-metric` (64) или `--text-h1`, всегда моно, всегда с подписью, что это за число |
| 4.7 | **Прозрачность — не инструмент иерархии.** Тише делается цветом и весом. `opacity` на тексте и на пульте с текстом съедает контраст незаметно для токенов и заметно для глаза: пульт доски на `opacity: .3` давал 1,53 при пороге 4,5 |
| 4.8 | **Третичный цвет не ставится на приглушённую поверхность.** `--color-text-hint` считан под белый и под фон (5,27 и 4,66), на `--color-surface-subtle` даёт 4,33 — на сотые ниже порога. На плашке, карточке-выборе и в заметке — `--color-text-detail` | прибор `contrast` |
| 4.11 | **Приглушённый цвет выбирается не по важности, а по обязательности прочтения.** Вопрос один: ЧТО БУДЕТ, ЕСЛИ ЭТО НЕ ПРОЧИТАЮТ? Ничего — `--color-text-hint` (часы, стрелка, номер строки, подсказка, дублирующая видимое). Человек чего-то не узнает — `--color-text-detail` (сроки, числа, состояния, права, имена, «11 из 17», «проверено 19 августа»). **Имя `--color-text-tertiary` устарело**: оно называет место в иерархии, а порог стоит на другой оси, и три промаха подряд пришли именно из этой подмены | сверка: у каждой приглушённой надписи спросить вопрос |
| 4.9 | **У экрана одно имя, и оно одинаково во всех местах**: заголовок листа, вкладка, ссылка из другого экрана, служебная полоса листа. «Задания» в шапке и «работы» в полке вкладок — через месяц вопрос «это один экран или два». Слово не влезает — меняется не слово, а число вкладок | сверка списком имён |
| 4.10 | **Индикатор состояния — значащая графика, у неё свой порог 3,0.** Переключатель, точка, галочка считаются **парой**: кружок к дорожке и дорожка к карточке за ней. Серое на сером давало 1,4–1,7, и включённость приходилось угадывать по положению. **Тень не контур**: `--shadow-xs` — альфа 0,03 и в тёмной теме её нет вовсе. Приборы графику не меряют — смотрится глазами при приёмке | глазами, обе темы |

## 5. Акцент

| # | Правило | Проверка |
|---|---|---|
| 5.1 | **Одна акцентная заливка на экран** (две — если состояние и главное действие рядом) и **не больше трёх акцентных надписей**. Все они про одно: что делать дальше | прибор `accents`: заливок ≤ 2, надписей ≤ 3 |
| 5.2 | Состояние («идёт сейчас», «близкий срок») показывается **полосой 2 px слева + подписью**, не обводкой по периметру и не заливкой | нет карточек с акцентной рамкой по всему периметру |
| 5.3 | Действия внутри списков — обычным текстом с приглушённым подчёркиванием, не коралловым | прибор `accents` считает их надписями |
| 5.4 | Полосы прогресса, столбики графиков, разделители — `--color-border-strong` или белый с прозрачностью. Акцентом они не красятся никогда: длина полосы уже несёт значение, а двадцать коралловых полосок в рельсе съедают единственный акцент | прибор `accents` считает каждую полоску заливкой |
| 5.5 | Акцентный текст — `--color-accent-text`, заливка — `--color-accent-solid`. Пары не смешиваются | значения только из этих токенов |
| 5.6 | Вес несёт типографика: важное крупнее и плотнее, а не цветнее | — |
| 5.7 | Активный инструмент доски отмечается нейтральной заливкой `--color-surface-subtle`, не акцентной: акцент на экране урока принадлежит поднятой руке | прибор `accents` |

### 5а. Зелёный «дальше» — второй цвет со смыслом

| # | Правило | Проверка |
|---|---|---|
| 5.8 | **Два цвета, два смысла, никакого перекрытия.** Коралловый — то, что **горит**: срок, отмена, потеря, опасное действие, поднятая рука, «идёт сейчас». Зелёный (`--color-go-*`) — **решение и перспектива**: работа принята, тест сдан, урок пройден, слово выучено, согласие дано, путь открыт, «можно дальше» | глазами по списку ниже |
| 5.9 | Зелёного ровно столько же, сколько кораллового: **одна заливка на экран**, надписей — до трёх. Второй цвет без лимита даёт ёлку быстрее, чем один | прибор `accentsGo` |
| 5.10 | Однородный столбец списка — не акцент: оценки, «пройдено», «сдано» в журнале красятся зелёным все и одинаково. Одна зелёная метка среди серых — враньё: глаз читает её как выделение | глазами |
| 5.10а | **Полоса — не заливка.** Всё тоньше 6 px по одной из сторон — графика, а не площадь, и в лимит заливок не идёт: четыре полоски прогресса в списке курсов — однородный столбец, а не четыре акцента | тот же прибор, счётчик `линий` |
| 5.11 | Зелёная **заливка** — только у главного шага вперёд и только там, где на экране нет конкурирующего кораллового действия. Где есть и срок, и решение — срок берёт заливку, решение берёт обводку | приборы `accents` + `accentsGo` |
| 5.12 | **Одинаковая надпись — одинаковый вес.** Если слова кнопки повторяются в двух состояниях («Закрыть страницу»), она в обоих либо заливка, либо обводка: разный вес у одних и тех же слов читается как разный смысл. И заливку не получает `no-op` — кнопка, за которой решение уже принято | сверка кнопок по состояниям |
| 5.13 | Зелёный — не `success`. `success` говорит «операция прошла» (системное сообщение формы), `go` говорит «решено, можно дальше» (смысл учёбы). Смешивать токены нельзя, даже когда оттенки похожи | — |
| 5.14 | Семья зелёного зависит от режима, а не от экрана: по умолчанию **мох** `#2f8a56` — спокойный и ровно ложится в тёмную тему; в `data-mode="kids"` — **лист** `#619b21`, теплее и звонче. Экраны не переписываются — меняются только токены (**было склеено в ячейку 5.12**: два правила стояли в одной строке таблицы, второе без номера и потому нецитируемое) | `tokens.css`, раздел 4 |

**Зелёному** — принятая работа и оценка за неё, сданный тест, пройденный урок, выученное слово,
данное согласие, полоса пути курса, «11 из 17», пройденные шаги настройки, подтверждение и
кнопка следующего шага.

**Коралловому** — горящий срок, несданная работа, отмена занятия, удаление, выход из урока,
поднятая рука, точка «идёт сейчас».

**Никому** — метрики внимания, столбики графиков, номера, служебные подписи: цифра и длина
полосы несут смысл без цвета (ПРАВИЛА 5.4).

## 6. Состояния

| # | Правило |
|---|---|
| 6.1 | У каждого экрана пять состояний: наполнено · пусто · загружается · отказ · частичный отказ. Сдать только «наполнено» — не сдать экран |
| 6.2 | Пусто — объясняет словами, что здесь будет и что сделать сейчас; всегда есть одно действие |
| 6.3 | Загружается — говорит, что придёт первым, и не мигает пустотой |
| 6.4 | Отказ — называет **причину** («медиасервер не отвечает», «нет права»), что уцелело и одно действие. «Что-то пошло не так» запрещено |
| 6.5 | **Частичный отказ — самостоятельное состояние**, а не разновидность отказа. Сломанное называется **внутри своей области** (доска — в области доски), без карточки поверх всего кадра: карточка поверх врёт, будто не работает ничего |
| 6.5а | В частичном отказе названы три вещи: **что работает**, **что нет**, **что с данными** («версия 12:04 сохранена»). Пульты в этом состоянии не прячутся |
| 6.5б | Частичный отказ нужен там, где экран собирается из НЕСКОЛЬКИХ независимых источников: комната урока, оба кабинета, кабинет предмета, задания, «Моя учёба», «Источники мира». Один источник — либо всё, либо ничего, отдельного состояния не требуется: вход и регистрация, демо |
| 6.5в | **Состояние принадлежит операции, а не экрану.** Где на одном экране два режима (перенести / отменить), там ДВА набора текстов «работает / не работает / что с данными». Общая ветка по экрану склеивает их молча: заголовок говорит «Отмена», а отказ — «новое время сохранено» | сверка текстов по режимам |
| 6.5г | **Рельс не обещает того, чего экран в этом состоянии сделать не может**, и это относится ко всему рельсу вместе с подписью под кнопкой: обещание не перестаёт быть обещанием от мелкого кегля. Пока служба молчит — прочерк и «ничего не уйдёт», а не «14 учеников получат» | глазами по всем состояниям |
| 6.5д | **В развилке состояний три ветки, а не две.** «Не наполнено» — не состояние: в загрузке ничего не сломано, и «пока служба молчит» там такая же ложь, как обещание в отказе | сверка текстов по трём состояниям |
| 6.6 | **Макет не прыгает** между «загружается» и «наполнено»: заглушка занимает ровно то же место, что содержимое. Следствия: шапка со сводкой стоит всегда (без данных — прочерк и ровная полоска); сообщение «отправляем» не встаёт новым блоком над формой, а живёт в строке, которая есть всегда; введённое при отправке не пропадает | прибор `jump` по `data-geo` |
| 6.7 | Места, которые обязаны стоять на месте, помечены `data-geo="имя"`. Одно имя на содержимом и на его заглушке — так в коде записано «эти два занимают одно место» | тот же прибор |
| 6.7а | **Имя `data-geo` вешается ТОЛЬКО на то, что обязано стоять во всех состояниях.** Если место именовано, оно не меняет размер от длины текста: высота держится числом строк (`calc(N * var(--leading-*) * 1em)`), а не подгонкой слов под пиксели. Блок, который в отказе исчезает по устройству, имени не получает | прибор `jumpStates` |
| 6.7б | **Отменённое занятие не удаляет свой чат.** Вопросы и ответы — часть учёбы: читать можно всегда, писать нельзя, и рядом сказано, куда идти с новыми вопросами | лист «Чат» |
| 6.7в | **Список для `sc-for` — список сущностей с `id`, а не подписей.** Массив строк вынуждает вписывать `data-val` руками, и подпись расходится с ключом молча: экран показывает один случай под именем другого, а приборы этого не видят — разметка цела, врёт только смысл | сверка `data-val` с картой состояний |
| 6.7г | **Служебная логика не заходит внутрь кадра.** Раскраска переключателей из полосы не имеет права красить продуктовые контролы: на тёмном экране проектора светлые токены дали 3,23 при пороге 4,5. Внутри кадра — своя пара цветов (`--color-*-on-video`) | прибор `contrast` по подэкранам |
| 6.7д | **Служебное и продуктовое различаются ИМЕНЕМ, а не местом.** Переключатель полосы — `data-sw`, кнопка внутри экрана — `data-pick`. Одно имя на две разные вещи восемь дней заставляло прогон мерить экран ожидания под именем проектора: `querySelector` берёт первое совпадение и не жалуется (решение владельца 22 августа) | поиск `data-sw` внутри `[data-audit-scope]` — должен быть пуст |
| 6.7е | **Прогон обязан падать громко, когда лист не ожил.** По мёртвому экрану все приборы честно говорят ok — он не перекрывается, не обрезается, не прыгает. Перед замерами проверяется: кадр есть, переключатель отвечает, страница не кричит в консоль | приборы `alive` и `pageErrors` |
| 6.8 | Переключатель состояния не стирает стили шаблона: скрывая элемент, запоминай его `display` и возвращай именно его (**было 6.6** — номер занят правилом «макет не прыгает»; старые отчёты со ссылкой 6.6 смотреть по смыслу) | сверка после переключений |

## 7. Цели нажатия и клавиатура

| # | Правило |
|---|---|
| 7.1 | Главная кнопка — `--tap-min` (44) по высоте; в режиме kids 48 |
| 7.1а | **Одно действие в строке — цель сама строка**, высота `--tap-min`. Кнопок внутри тогда нет, и 12 строк журнала × 44 = 528 px — правильная цена, а не конфликт |
| 7.1б | **Действий два и больше — цель кнопка**: `--control-height-sm` (34, kids 40), между кнопками `--space-2`. Строка остаётся 44: плотность списка не растёт. Оба случая показаны живыми в виде «правила» «Комнаты урока» |
| 7.2 | Вторичные контролы в плотных списках — не ниже `--control-height-sm` (34); цель нажатия при этом даёт **строка целиком** |
| 7.3 | Фокус видно всегда: `--focus-ring`, две тени, никогда `outline: none` без замены |

## 10. Создание: курс и занятие

| # | Правило | Проверка |
|---|---|---|

## 11. Цвет одним куском (решение владельца §57)

До этого цвет был размазан по трём местам — 5.1, 5а и 10.2, и в двух из них главное действие
было коралловым. Здесь всё вместе и в окончательном виде.

> **Главное действие — зелёное. Коралловое — только тревога и уход.**

| # | Правило | Проверка |
|---|---|---|
| 11.1 | **Зелёная заливка — у главного действия экрана.** Главное — то, ради чего экран открывают: «Начать урок», «Опубликовать курс», «Сохранить правку», «Сдать работу», «Принять заявку», «Дальше» в мастере, «Войти» | прибор `accentsGo` |
| 11.2 | **Коралловое — тревога и уход, и больше ничего.** Тревога: горящий срок, поднятая рука, «идёт сейчас», потеря связи. Уход: выйти, завершить, отменить, удалить, отозвать, снять с публикации | `accents` |
| 11.3 | **Коралловое действие не берёт заливку без нужды:** уход и отмена — обводка коралловым. Заливка коралловым остаётся только тому, что горит сейчас (метка «рука» на плитке ученика) | `accents` |
| 11.4 | **На экране одна заливка всего**, какого бы цвета она ни была. Две заливки — только когда рядом главное действие и горящее состояние | `accents` + `accentsGo` |
| 11.5 | **Приватность цветом не показывается вовсе.** Ни зелёной заливки, ни зелёной рамки: это не действие и не «можно дальше». Показатель — пара «точка + надпись» внизу того кадра, к которому относится | глазами |
| 11.6 | **Что отменено этим решением.** 5.11 («зелёная заливка только там, где нет конкурирующего кораллового») и строка «коралловому — кнопка следующего шага» из 5а. **Номера не перенумерованы** — на них ссылаются старые отчёты; при расхождении старого и 11.x верно 11.x | — |
| 11.7 | **Заливка меняется вместе со смыслом, а не с местом.** Одна и та же кнопка не бывает зелёной на одном экране и коралловой на другом | сверка по пулу |
| 11.8 | **Проба на тревогу: портится ли это от ожидания?** Коралловое — то, что через час станет неправдой или уже стоит человеку чего-то. Поднятая рука портится (ученик ждёт ответа сейчас, через минуту вопрос бессмыслен) — она коралловая, и это единственная коралловая заливка в комнате. Непрочитанное в чате не портится: сообщение никуда не денется, счётчик — число, а не тревога, и берёт нейтральный цвет с весом 500. Исключение с обеих сторон одно: **чат ИДУЩЕГО занятия** — вопрос там живёт до конца урока, поэтому счётчик берёт коралловую **надпись**, но не заливку: заливка уже отдана руке (ПРАВИЛА 11.4) | приборы `accents` + сверка списком |

**Пример из продукта, ради которого правило сведено:** на странице курса «Опубликовать»
было коралловым, а в мастере коралловым же был каждый «Дальше». Когда коралловым
залит каждый следующий шаг, он перестаёт указывать на что-либо.

## 12. Приглушённая дверь (решение владельца §59)

Старого оформления в продукте не остаётся. Где листа нет и рисовать не будем — дверь
приглушается: **видна, названа, не нажимается, и рядом сказано почему.**

| # | Правило | Проверка |
|---|---|---|
| 12.1 | **Приглушает цвет и вес, не прозрачность.** `opacity` гасит всё вместе с объяснением и делает нечитаемым то, ради чего дверь оставлена | в листах нет `opacity` на дверях |
| 12.2 | **Название двери — `--color-text-secondary`, вес 400** (вместо `--color-text` и 500 у живой). Граница — `--color-border` без заливки, фон — `--color-surface-subtle` | прибор `contrast` |
| 12.3 | **Строка «почему нельзя» берёт полный контраст** (`--color-text-secondary`, порог 4,5), потому что это **часть смысла**, а не сноска (ПРАВИЛА 4.7). Приглушено название двери, а не объяснение | `contrast` |
| 12.4 | **Говорит о сроке или условии, а не о запрете.** «Этой части пока нет», а не «нет доступа»: второе человек читает как свою вину | глазами |
| 12.5 | **Не нажимается по-настоящему:** `aria-disabled="true"`, `tabindex="-1"`, `cursor: default`. Мёртвая кнопка, которая выглядит живой, хуже отсутствующей | прогон щёлкает и ничего не меняется |
| 12.6 | **Цель нажатия остаётся полной** (`--tap-min`): дверь не сжимается и не уезжает вниз списка — иначе это не «пока нет», а «спрятали» | `tapTargets` |
| 12.7 | **Приглушённых дверей не больше трёх подряд в одном списке.** Четыре и больше — это не двери, а витрина несуществующего; такой список сворачивается в одну строку «ещё нет: журнал, повторение, учреждение» | глазами |

## 14. Кнопка либо отвечает, либо объявлена немой (прибор 19)

Восемнадцать приборов меряют картинку. Мёртвая кнопка с верной разметкой, верным контрастом
и верной целью нажатия проходит их все; пустая рамка под именем «перетаскивание»
геометрически безупречна. Оба дефекта нашёл владелец глазами, и оба стоили того, что
разработчик собрал по листу неработающий экран. Девятнадцатый прибор (`audit-clicks.js`,
стенд `clicks-run.html`) нажимает каждый элемент и сверяет снимки до и после.

| # | Правило | Проверка |
|---|---|---|
| 14.1 | **Кнопка либо отвечает на нажатие, либо объявлена немой словами** — `data-still="что она делает в продукте и где это показано на листе"`. Лист не продукт, и часть кнопок стоит на нём показом; но необъявленное молчание неотличимо от дефекта, а список объявленных немых — это и есть наряд разработчику | прибор `flClicks`: молчащих без объявления — 0 |
| 14.2 | **Объявление не подкладывается живой кнопке.** `data-still` на кнопке, которая отвечает, — тот же обман наоборот | тот же прибор, счёт «объявлено молчание, а кнопка отвечает» |
| 14.3 | **Приглушённая дверь обязана молчать** (ПРАВИЛА 12.5), и `aria-disabled` для неё — уже объявление: оно доходит до читалки экрана. Дверь, которая что-то меняет, — дефект; дверь без `tabindex="-1"` — дефект | тот же прибор |
| 14.4 | **Нажатие на уже выбранный случай молчит законно.** Проверяется соседом: если другой случай той же группы кадр меняет — группа жива | тот же прибор |
| 14.5 | **Два имени случая не дают один снимок кадра.** Совпавшие снимки означают, что одно из имён обещает состояние, которого в разметке нет: подпись есть, ветки нет. Это и есть та слепота, из-за которой экран восемь дней показывал первый случай под именем третьего | прибор `flCases`: близнецов — 0 |
| 14.6 | **Случай, недоступный в текущем состоянии, не снимается вовсе.** Щёлкнув по скрытой кнопке, прибор получает снимок предыдущего случая и объявляет два имени близнецами — на этом попался сам прибор в первом же прогоне. Недоступное честно помечается «не снято» | тот же прибор, список `missed` |
| 14.7 | **Прибор состояние листа не восстанавливает.** Восстановление угадыванием врёт хуже, чем грязный лист: каждому проходу даётся свежий кадр | стенд `clicks-run.html` |
| 14.8 | **Прибор доказан провалом, а не осмотром.** Самопроверка подкладывает четыре кнопки с известным поведением (немая · объявленная · живая · живая дверь) и обязана поймать две из четырёх; отдельно проверяется, что заведомо мёртвый лист не назван живым | `flClicksSelfTest()` + образец `выгрузка/проверка-мёртвого-листа.dc.html` |

**Как прибор нашёл дефект в себе.** В первом заходе самопроверки живая кнопка и живая дверь
делили один флажок появления, и к очереди двери он уже был поднят — «изменение» не отличалось
от нуля, и прибор провалил собственную проверку тем самым дефектом, который ищет.
Это его лучшая рекомендация: проверка была написана до того, как стал известен её результат.
