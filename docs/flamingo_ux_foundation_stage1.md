# Flamingo — Этап 1: UX-фундамент веб-приложения

**Версия:** 1.0  
**Дата:** 12.06.2026  
**Статус:** базовый документ для дизайна и разработки  
**Назначение:** определение пользовательских сценариев, архитектуры информации и карты экранов MVP

---

## 1. Обзор целевых ролей

Платформа Flamingo служит четырём ключевым ролям, каждая с собственным journey и целями:

| Роль | Возраст / Тип | Задачи | Уровень цифровой грамотности |
|---|---|---|---|
| **Ученик младших классов** | 7–11 лет | Участие в занятиях, выполнение ДЗ, просмотр прогресса | Низкий–средний; интерфейс управляется через родителя |
| **Подросток** | 12–17 лет | Самостоятельное управление учебой, видео-занятия, ДЗ, рейтинги | Средний–высокий; полная самостоятельность |
| **Взрослый слушатель** | 18+ лет | Обучение на курсах, сертификация, фокус на результате | Высокий |
| **Родитель** | 25–60 лет | Контроль учёбы ребёнка, оплата, уведомления | Средний |
| **Преподаватель / Репетитор** | 25–70 лет | Создание курсов и занятий, проведение уроков, оценка, аналитика | Высокий |
| **Администратор учреждения** | 30–60 лет | Управление пользователями, группами, отчёты, интеграции | Высокий |

---

## 2. User Stories по ролям

### 2.1 Ученик младших классов (7–11 лет)

```
US-ST-001 | Онбординг и создание аккаунта
As a родитель младшего школьника
I want to создать аккаунт ребёнка и дать согласие на обработку данных
So that мой ребёнок может начать обучение на платформе

Acceptance Criteria:
- Форма регистрации детского аккаунта с проверкой email родителя
- Чекбокс согласия на 152-ФЗ (обработка данных детей)
- Email-верификация и установка пароля родителем
- Автоматическое создание "детского интерфейса" (упрощённая навигация)
- Уведомление: "Аккаунт создан, готов к первому занятию"
```

```
US-ST-002 | "База тест" — определение базового состояния
As a младший школьник (управляемо родителем)
I want to пройти 3-этапный видеотест при первом входе
So that система понимает мои базовые возможности внимания и эмоции

Acceptance Criteria:
- Видеовызов с 3 этапами (спокойное состояние, концентрация, игровое)
- Инструкции простые, шрифт крупный, картинки-подсказки
- Медиапайп анализирует лицо on-device, метрики не отправляются на сервер
- По окончании: краткое резюме "Твоё начальное состояние" с эмодзи
- Кнопка "Готов учиться!" → в расписание
```

```
US-ST-003 | Просмотр расписания и записей на занятия
As a младший школьник
I want to увидеть свои занятия на неделю большими карточками с иконками
So that я знаю, когда и на какой предмет мне идти учиться

Acceptance Criteria:
- Календарь на неделю (пн–вс) в формате большых карточек
- Каждая карточка: значок предмета, имя преподавателя, время, статус (на 10 мин, идёт, прошло)
- Цветовая кодировка по предметам (математика=жёлтый, литература=синий и т.д.)
- Кнопка "Присоединиться" за 5 минут до начала
- Для младших: картинка преподавателя вместо текста
```

```
US-ST-004 | Участие в видео-занятии с CMF (внимание)
As a младший школьник
I want to видеть преподавателя и экран, писать в чат, видеть свою камеру
So that я могу учиться, взаимодействовать и понимать, что преподаватель меня видит

Acceptance Criteria:
- Видеоокно преподавателя (большое, слева), экран с материалом (справа)
- Моя камера включена, я вижу себя в мини-окне
- Чат справа (только текст для младших, эмодзи приветствуются)
- На фоне: незаметная CMF-аналитика (MediaPipe анализирует лицо, не отправляя видео)
- После занятия: инсайт "Ты был сосредоточен 85% времени" с котёнком-мотиватором
- Статус внимания сохраняется локально (UBP на устройстве)
```

```
US-ST-005 | Выполнение домашнего задания через виртуальный рабочий стол
As a младший школьник
I want to загрузить фото/файл ответа или написать текст в редактор
So that я сдам ДЗ преподавателю

Acceptance Criteria:
- Вкладка "Мои ДЗ" в личном кабинете
- Для каждого ДЗ: описание, срок, статус (не начинал, в процессе, сдал, оценено)
- Кнопка "Загрузить файл" (фото, PDF) или "Написать ответ"
- Поле для текста с базовым форматированием (жирный, курсив, список)
- После загрузки: "Отправлено преподавателю" + дата отправки
- Если время истекло: предупреждение "Срок прошёл, но ты можешь сдать поздно"
```

```
US-ST-006 | Просмотр оценки и обратной связи
As a младший школьник
I want to увидеть оценку за ДЗ и комментарий преподавателя
So that я понимаю, где ошибка и как улучшить

Acceptance Criteria:
- Уведомление: "Преподаватель оценил твою работу"
- На странице ДЗ: оценка (звёзды или баллы), комментарий текстом
- Для младших: эмодзи-реакция от преподавателя (👍 ✨ 🎉 💪)
- Опция "Переделать" для повторной сдачи (если разрешено преподавателем)
```

```
US-ST-007 | Просмотр профиля прогресса
As a младший школьник
I want to видеть мой прогресс по предметам: оценки, посещаемость, уровень внимания
So that я вижу, где я хорошо, а где нужно стараться больше

Acceptance Criteria:
- Страница "Мой прогресс" с вкладками: Оценки, Внимание, Посещаемость
- Оценки: список с датами, предметами, баллами (таблица или карточки)
- Внимание: график по неделям (среднее % внимания), инсайты ("На математике ты концентрируешься лучше")
- Посещаемость: календарик с зелёными/красными днями
- Для младших: большой шрифт, минимум текста, картинки-мотиваторы
```

### 2.2 Подросток (12–17 лет)

```
US-ST-008 | Самостоятельная регистрация
As a подросток (12+)
I want to создать аккаунт с email и паролем самостоятельно (с согласием родителя по email)
So that я смогу управлять своей учёбой

Acceptance Criteria:
- Форма: email, пароль, имя, класс
- Проверка возраста → если <18, отправляется письмо родителю "Подтвердите, что согласны"
- После подтверждения родителем: аккаунт активен
- Подростки видят "взрослый" интерфейс (без упрощений из младших классов)
```

```
US-ST-009 | Выбор и запись на курсы
As a подросток
I want to просмотреть каталог курсов, прочитать описание и записаться
So that я могу расширить свои знания по интересующим предметам

Acceptance Criteria:
- Страница "Курсы": фильтры по уровню (7 кл, 8 кл…), по предмету
- Карточка курса: название, преподаватель, описание, кол-во уроков, дата начала
- Кнопка "Записаться" → добавление в расписание
- Статус: ожидание, активен, завершён
- Уведомление: "Ты записался на курс [Название]"
```

```
US-ST-010 | Видеозанятие с полной CMF-аналитикой и предложениями
As a подросток
I want to видеть свой уровень внимания в реальном времени и рекомендации системы
So that я могу улучшать фокус и планировать учёбу

Acceptance Criteria:
- Видеозанятие (как US-ST-004, но более взрослая визуализация)
- Дополнительно: мини-график "Внимание %" в углу (обновляется каждые 5 сек, on-device)
- По окончании: полный отчёт CMF (средний %, пики и падения внимания)
- Рекомендация: "Твоё внимание падает после 40 минут — попробуй 10-минутный перерыв"
- Все данные (UBP, метрики) хранятся локально; на сервер → только агрегаты
```

```
US-ST-011 | Рейтинговая система и достижения
As a подросток
I want to видеть свой рейтинг в группе, количество баллов, значки/медали за достижения
So that я мотивирован учиться лучше и конкурировать дружественно

Acceptance Criteria:
- Вкладка "Рейтинг": топ-10 в группе или классе, твой текущий ранг
- Баллы за: занятие (посещение), выполнение ДЗ, хорошую оценку, регулярность
- Значки: "Спешу учиться" (7 дней подряд), "Отличник" (средний балл >4.5), "Внимательный" (CMF >80%)
- Награды отображаются на профиле
```

```
US-ST-012 | Персональные рекомендации на основе CMF и поведения
As a подросток
I want to получить предложение курсов, время занятий или отдельных материалов на основе моих данных
So that моя учёба оптимизирована под мой стиль и биоритмы

Acceptance Criteria:
- "Рекомендации для тебя" (карусель) на главной странице
- Примеры: "Ты сконцентрирован в 8–10 часов утра — попробуй занятия в это время"
- "Тебе нравятся видеоматериалы (100% внимания на видео vs 60% на текст) — вот подходящие курсы"
- Данные основаны на агрегированных метриках (не на сыром видео)
```

### 2.3 Взрослый слушатель курсов (18+ лет)

```
US-ST-013 | Регистрация и выбор курсов
As a взрослый слушатель
I want to зарегистрироваться и записаться на профессиональные или развивающие курсы
So that я могу получить новые навыки и сертификат

Acceptance Criteria:
- Стандартная регистрация (email, пароль, имя)
- Каталог "Для взрослых": профессиональные курсы, языки, хобби
- Сортировка: по популярности, рейтингу, длительности, цене
- Кнопка "Записаться" / "Начать бесплатно" (если часть курса бесплатна)
- Мой курсы: прогресс по каждому курсу (% пройденного)
```

```
US-ST-014 | Видеозанятия и учебные материалы
As a взрослый слушатель
I want to смотреть записи занятий, скачивать материалы, делать заметки
So that я учусь в удобном темпе

Acceptance Criteria:
- Видеоплеер с паузой, скоростью (0.75x, 1x, 1.25x, 1.5x)
- Секция "Материалы": загрузка PDF, документы, ссылки
- Инструмент "Мои заметки": редактор, привязка к времени видео
- Прогресс: отметить видео как "просмотрено" → разблокировка следующего
```

```
US-ST-015 | Сертификация
As a взрослый слушатель
I want to пройти финальный тест и получить сертификат (PDF с QR)
So that я могу подтвердить свои новые навыки

Acceptance Criteria:
- После завершения курса: кнопка "Финальный тест"
- Тест: мин. 10 вопросов, 70% проходной балл
- При успехе: PDF-сертификат скачивается, QR-код ведёт на страницу верификации
- Сертификат на платформе: возможность поделиться в соцсетях или добавить в резюме
```

### 2.4 Родитель

```
US-ST-016 | Регистрация и связь с ребёнком
As a родитель
I want to создать аккаунт и связать его с аккаунтом ребёнка
So that я могу следить за его прогрессом

Acceptance Criteria:
- Регистрация: email, пароль, имя родителя, связь с ребёнком (по коду или email ребёнка)
- Проверка: отправляется уведомление ребёнку "Родитель просит доступ" → подтверждение
- После связи: "Дети" в боковом меню (если несколько детей)
```

```
US-ST-017 | Просмотр сводки по ребёнку
As a родитель
I want to видеть расписание ребёнка, его оценки, посещаемость и CMF-метрики
So that я знаю, как дела у ребёнка в школе и могу помочь

Acceptance Criteria:
- Дашборд "Обзор [Имя ребёнка]": 4 карточки
  1. Расписание на неделю (предметы, время)
  2. Последние оценки (таблица)
  3. Посещаемость (%)
  4. "Внимание" (среднее по неделе, график)
- Каждая карточка кликабельна → развёрнутый вид
- Уведомления: новая оценка, пропуск занятия, выполнено ДЗ
```

```
US-ST-018 | Уведомления и контроль
As a родитель
I want to получать push и email-уведомления о важных событиях
So that я всегда в курсе

Acceptance Criteria:
- События: новая оценка, пропуск, выполнено ДЗ, CMF-инсайты ("ребёнок невнимателен на истории")
- Настройки уведомлений: выбор канала (push, email), типов событий
- Возможность отключить для определённого ребёнка или предмета
- Уведомление содержит: что произошло, дата, ссылка на детали
```

```
US-ST-019 | Просмотр CMF-данных и рекомендаций
As a родитель
I want to видеть анализ внимания ребёнка (CMF) и рекомендации платформы
So that я понимаю его сильные/слабые стороны и могу помочь

Acceptance Criteria:
- Вкладка "Анализ": графики внимания по предметам, по дням недели
- Инсайты: "Лучше всего [Имя] сосредоточена на математике (88% vs 65% в среднем)"
- Рекомендации: "Попробуйте заниматься в 9 утра, когда внимание выше"
- Предупреждение: если средний CMF <50%, красная полоса с совет
```

### 2.5 Преподаватель / Репетитор

```
US-ST-020 | Регистрация и верификация
As a преподаватель
I want to создать аккаунт, заполнить профиль и подтвердить квалификацию
So that я смогу создавать курсы и занятия

Acceptance Criteria:
- Регистрация: email, пароль, ФИ, специальность, образование, опыт
- Загрузка документа (диплом, сертификат) для верификации
- Статусы профиля: ожидание модерации → верифицирован → готов преподавать
- Карточка преподавателя (публичный профиль): фото, описание, рейтинг
```

```
US-ST-021 | Создание курса (конструктор)
As a преподаватель
I want to создать курс с названием, описанием, уровнем сложности и связанными занятиями
So that я смогу предложить структурированное обучение

Acceptance Criteria:
- Форма курса: название, описание, уровень (1–11 кл, взрослый), предмет, язык
- Структура: разделы → занятия в разделе (drag-and-drop для переупорядочения)
- Для каждого раздела: название, описание, обложка (изображение)
- Кнопка "Сохранить как черновик" → "Опубликовать" → курс видим ученикам
- Редактирование курса: изменение названия, добавление новых разделов (студенты видят обновления)
```

```
US-ST-022 | Создание занятия (конструктор)
As a преподаватель
I want to создать одиночное занятие с материалами, расписанием трансляции и методиками
So that я смогу проводить структурированные видеоуроки

Acceptance Criteria:
- Форма занятия: название, описание, продолжительность (в минутах), дата/время начала
- Материалы: загрузить слайды (PDF, PPT), ссылки на видео, текстовые материалы
- Расписание: одноразовое занятие или по расписанию (пн/вт/ср и т.д., время)
- Опции: включить камеру, демонстрацию экрана, чат, домашние задания
- Черновик → опубликовать → отправить уведомление ученикам "Новое занятие доступно"
```

```
US-ST-023 | Проведение видеозанятия
As a преподаватель
I want to вести видеотрансляцию с управлением участниками, демонстрацией и чатом
So that я могу эффективно обучать группу студентов

Acceptance Criteria:
- Плеер: моя камера (основной видеопоток), демонстрация экрана (слайды/документ)
- Панель: список участников (онлайн/офлайн), чат, кнопки (пауза видео, запись, завершить)
- Запись занятия: сохраняется автоматически, доступна для просмотра позже
- По окончании: ученикам отправляется ссылка на запись + материалы
- CMF-инсайт для преподавателя: "Средняя внимание класса была 72%, пик внимания — при объяснении [темы]"
```

```
US-ST-024 | Создание и оценка домашних заданий
As a преподаватель
I want to создать ДЗ, установить срок и оценивать ответы учеников
So that я смогу управлять процессом обучения

Acceptance Criteria:
- Создание ДЗ: название, описание (с форматированием), тип (файл, текст, тест), срок сдачи
- Публикация: выбрать занятие или группу, отправить уведомление
- Просмотр ответов: список студентов, статусы (не сдал, сдал, опаздал)
- Оценивание: открыть ответ, добавить оценку (баллы, звёзды), комментарий текстом
- После оценки: ученик получит уведомление + может переделать (если разрешено)
```

```
US-ST-025 | Просмотр аналитики по группе
As a преподаватель
I want to видеть статистику по группе: средний CMF, успеваемость, посещаемость, рейтинги
So that я могу оптимизировать методику преподавания

Acceptance Criteria:
- Дашборд группы: название, кол-во студентов, средний рейтинг
- Таблица: студент → CMF (среднее %), оценки (среднее), посещение (%), активность в чате
- Графики: CMF по занятиям (где класс теряет внимание?), успеваемость по предметам
- Инсайт: "Внимание падает после 30 минут" → рекомендация сделать перерыв
- Экспорт отчёта в Excel
```

```
US-ST-026 | Рейтинг и репутация преподавателя
As a преподаватель
I want to видеть свой рейтинг, отзывы от студентов и рекомендации системы
So that я понимаю, как улучшить преподавание

Acceptance Criteria:
- Профиль: рейтинг (звёзды), количество отзывов, средняя оценка учеников
```

## 3. Main Flow: Главный сценарий end-to-end

### Сценарий: «Преподаватель создал курс → Ученик записался → Занятие с CMF → ДЗ → Оценка → Родитель видит прогресс»

#### 3.1 Этап 1: Преподаватель создаёт курс и занятие

**Действующие лица:** Преподаватель (Иван), Администратор учреждения

**Предусловия:**
- Иван уже зарегистрирован, верифицирован
- Администратор создал группу "7Б Математика"

**Последовательность:**

1. **Иван входит** → Дашборд преподавателя, вкладка "Мои курсы"
2. **Нажимает "Создать курс"** → Форма:
   - Название: "Алгебра 7 класс"
   - Описание: "Линейные уравнения и функции"
   - Уровень: 7 класс
   - Предмет: Математика
3. **Добавляет раздел:**
   - "Раздел 1: Линейные уравнения" (3 занятия)
4. **Создаёт первое занятие:**
   - Название: "Введение в линейные уравнения"
   - Описание: "Основные понятия"
   - Дата/время: вт 10:00, каждую неделю
   - Загружает PDF со слайдами
5. **Публикует курс** → Уведомление отправляется ученикам группы "7Б Математика"

**Результат:** Курс видим в каталоге, первое занятие появилось в расписании.

---

#### 3.2 Этап 2: Ученик записывается и готовится к занятию

**Действующие лица:** Петя (ученик, 13 лет), Родитель Пети

**Предусловия:**
- Петя зарегистрирован, прошёл "базу тест"
- Родитель связан с аккаунтом Пети

**Последовательность (глазами Пети):**

1. **Петя входит** → Дашборд, вкладка "Расписание"
2. **Видит:** Новое занятие "Введение в линейные уравнения" на вт 10:00
3. **В понедельник вечером** получает уведомление:
   - Push: "Завтра в 10:00 — Алгебра с Иваном"
   - Email (у родителя): "Петя записан на занятие завтра"
4. **Вт 9:55** → Петя нажимает "Присоединиться" → Открывается видеоплеер и CMF-инициализация
   - Запрос доступа к камере: "Разрешить для анализа внимания"
   - "База тест" повторяется в мини-форме (30 сек): калибровка лица
   - UBP загружается с локального устройства (или создаётся новый сегмент)

**Результат:** Петя готов к занятию, система готовит CMF-анализ.

---

#### 3.3 Этап 3: Видеозанятие с CMF-анализом

**Действующие лица:** Иван (преподаватель), Петя (ученик), 20 других студентов

**Сценарий:**

1. **10:00 — Иван стартует трансляцию**
   - Его камера включена (лицо, верхняя часть), рядом экран с пошаговым решением уравнений
   - Чат открыт справа
2. **Петя видит:**
   - Лицо Ивана (слева, большое)
   - Экран с уравнением (справа)
   - Мини-окно себя (я в углу)
   - График "Внимание %" (верхний правый угол, обновляется каждые 5 сек)
   - На устройстве Пети: MediaPipe анализирует его лицо (камера видит Петю, но видео на сервер НЕ передаётся)
3. **Ивану видны:**
   - Список участников (иконки, имена, статус онлайн)
   - Сводка внимания класса (график)
   - Его собственная трансляция + демонстрация
4. **40 минут занятия:**
   - Иван объясняет, пишет на доске (демонстрирует экран с программой)
   - Петя смотрит, мозг концентрируется (внимание 85% первые 30 мин)
   - После 30 минут внимание начинает падать → 65%
   - Иван даёт 5-минутный перерыв (видит по графику, что класс устал)
   - После перерыва: Петя более внимателен (внимание восстанавливается до 78%)
5. **Конец занятия (10:40):**
   - Иван: "Домашнее задание — 3 уравнения на странице 45" (скидывает ссылку в чат)
   - Нажимает "Завершить" → трансляция записывается и отправляется ученикам
   - Петя видит: "Занятие завершено. Запись доступна" + "Твоё внимание: среднее 77%, пики и спады графика"

**CMF-механика (on-device, невидимо для пользователя):**
- MediaPipe анализирует: положение лица, направление взгляда, выражение (активность)
- Метрики вычисляются каждые 2 секунды (in-browser)
- На сервер отправляются только агрегаты: `{timestamp, average_attention, session_id}`
- Сырое видео НИ когда не покидает устройство
- UBP (биопаспорт) обновляется локально: новый профиль внимания за эту сессию

**Результат:** Петя имеет запись занятия + инсайт о своём внимании. На сервере хранятся только обезличенные метрики.

---

#### 3.4 Этап 4: Домашнее задание и сдача

**Действующие лица:** Петя, Иван

**Сценарий (Петя):**

1. **Вечер того же дня** → Петя заходит в "Мои ДЗ"
2. **Видит ДЗ:**
   - Название: "Решить 3 уравнения"
   - Описание: "Стр. 45, №1, №2, №3. Срок: чт 23:59"
   - Материалы: ссылка на запись занятия, PDF с уравнениями
3. **Петя открывает "Виртуальный рабочий стол":**
   - Редактор с клавиатурой + возможность загрузить файл
   - Пишет решение в текстовый редактор (или загружает фото листка тетради)
4. **Ср 19:00 — Петя сдаёт:**
   - Нажимает "Отправить" → "Отправлено преподавателю"
   - Видит статус: "Ожидание проверки"

**Сценарий (Иван):**

1. **Чт утром** → Иван заходит в "Оценивание"
2. **Видит список:** 21 студент, статусы (15 сдали, 3 опаздали, 3 не сдали)
3. **Кликает на Петю** → Видит его ответ (PDF с решением)
4. **Оценивает:**
   - Выставляет оценку: 5 (отлично)
   - Комментарий: "Молодец! Уравнение решено верно, но обрати внимание на оформление."
   - Нажимает "Готово"

**Результат:** Петя получает уведомление о готовой оценке.

---

#### 3.5 Этап 5: Петя видит оценку и обратную связь

**Действующие лица:** Петя

**Сценарий:**

1. **Пт 10:00** → Push-уведомление: "Иван оценил твою работу! 5 ⭐"
2. **Петя заходит** в ДЗ → видит:
   - Оценка: 5 ⭐
   - Комментарий преподавателя
   - Кнопка "Переделать" (если позволяет преподаватель)
3. **Профиль Пети обновляется:**
   - "Мой прогресс" → Оценки → новая строка (5 за Алгебру)
   - Рейтинг в группе: может подняться (если система расчитывает на баллы)

---

#### 3.6 Этап 6: Родитель видит прогресс

**Действующие лица:** Родитель Пети

**Сценарий:**

1. **Email-уведомление (Пт 10:05):**
   - "Петя получил оценку 5 за ДЗ по алгебре"
   - Ссылка на дашборд

2. **Родитель заходит** в кабинет:
   - Дашборд "Петя" → Вкладка "Оценки"
   - Видит новую строку: Алгебра, ДЗ, 5⭐, дата
   - Среднее за неделю: 4.6 (вырос с 4.3 благодаря этой оценке)

3. **Вкладка "Анализ":**
   - График CMF по дням: вт (на алгебре) — 77% внимания (хорошо)
   - Инсайт: "Петя хорошо сосредоточен на математике"
   - Рекомендация: "Продолжайте уроки математики по вторникам в это время"

4. **Уведомления:** Родитель активирует пуш-уведомления для новых оценок + еженедельный дайджест

**Результат:** Родитель имеет полную картину прогресса Пети: оценки, внимание, тренды.

## 6. Примечания к реализации

### 6.1 Адаптивность и доступность

- **Мобильная адаптивность:** Все экраны работают на сенсорных устройствах (планшеты, смартфоны). Видеозанятия и редакторы адаптируются для узких экранов.
- **WCAG 2.1 AA:** Контрастность, навигация клавиатурой, ARIA-метки.
- **Возрастная адаптация:** Размер шрифта, упрощение интерфейса для младших классов (меньше текста, больше иконок).

### 6.2 CMF и on-device обработка

- **Архитектура:** Сырые биометрические данные (видео с камеры) обрабатываются на клиенте (браузер + MediaPipe) без передачи на сервер.
- **API:** Клиент отправляет только агрегированные метрики: `{timestamp, session_id, average_attention_percentage}`.
- **UBP (биопаспорт):** Хранится локально (IndexedDB или LocalStorage); опционально зашифрованная синхронизация в облако.

### 6.3 Уведомления

- **Каналы:** Push (браузер), Email, in-app.
- **Типы:** Новое занятие, оценка, пропуск, выполнено ДЗ, CMF-инсайт, еженедельный дайджест (для родителя).
- **Управление:** Каждая роль может настроить типы и канал уведомлений.

### 6.4 Data Flow при главном сценарии

```
Преподаватель создаёт курс
  ↓ (API: создать курс, секцию, занятие)
PostgreSQL (хранение метаданных курса)
  ↓
Ученик видит в каталоге и записывается
  ↓ (API: записать ученика на курс)
PostgreSQL (связь студент-курс)
  ↓
Уведомление ученику + родителю (Email, Push)
  ↓
Время занятия (ученик присоединяется)
  ↓
LiveKit (видеотрансляция)
  ↓
Клиент: MediaPipe анализирует камеру → метрики внимания
  ↓
Клиент: UBP обновляется локально (IndexedDB)
  ↓
Клиент: отправляет агреги-метрики на сервер через WebSocket
  ↓
PostgreSQL (сохранить CMF-метрики за сессию)
  ↓
Запись занятия (S3 / Yandex Object Storage)
  ↓
Преподаватель создаёт ДЗ, выбирает группу
  ↓
PostgreSQL (хранить ДЗ, срок, описание)
  ↓
Ученик сдаёт ДЗ (загруженный файл)
  ↓
S3 (сохранить файл ответа)
  ↓
PostgreSQL (статус ДЗ → "сдан")
  ↓
Преподаватель оценивает ДЗ (оценка + комментарий)
  ↓
PostgreSQL (сохранить оценку)
  ↓
Уведомление ученику (оценка) + родителю (обновление прогресса)
  ↓
Дашборд родителя обновляется (оценка, CMF-тренды)
```

## 7. Ключевые предположения и ограничения (MVP)

### Предположения

1. **Каждый ученик имеет камеру/микрофон** на устройстве при участии в занятиях.
2. **Интернет-соединение стабильное** для video streaming и медиапайп-анализа.
3. **Браузер поддерживает** WebRTC, IndexedDB, Web Workers (для MediaPipe).
4. **MediaPipe достаточно точна** для базового анализа внимания по движениям лица и глаз.
5. **Родители хотят видеть CMF-метрики**, но не требуют их биомедицинской точности (это развлекательное предложение, не медицинский диагноз).

### Ограничения MVP

- **Блокчейн / NFT-сертификаты:** Отложены на итерацию 4; MVP использует PDF с QR-кодом.
- **VR/AR:** Отложены на итерацию 3.
- **Open API** (дроны, телескопы): Отложены на итерацию 2.
- **Neo4j** (графовая БД рекомендаций): MVP использует PostgreSQL.
- **Полный CMF R&D:** MVP использует open-source MediaPipe для базовой детекции внимания.
- **Мобильные приложения:** MVP — веб; React Native после стабилизации.
- **Многоязычность:** MVP — только русский (архитектура i18n-ready).
