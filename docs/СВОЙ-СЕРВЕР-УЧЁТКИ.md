# Учётные записи на своём сервере — что делает владелец

**Решение владельца 31.08.2026.** Хеширование пароля не влезает в 10 мс
процессорного времени бесплатного тарифа Cloudflare Workers. Из трёх путей выбран
свой сервер `82.147.71.204`: лимита нет, доступен argon2id.

Код написан и проверен живым проходом у меня: регистрация, вход, кука между
`flamingo.plus` и `api.flamingo.plus`, выход. **До самого сервера я дотянуться не могу**
— сети до него из моей среды нет, а доступы через чат я не приму. Шаги ниже — ваши руки.

## Что меняется

| | Было | Стало |
|---|---|---|
| Где считается пароль | функция Cloudflare Pages | ваш сервер, Django |
| Чем считается | PBKDF2, 100 000 повторов, 46 мс | **argon2id**, 64 МБ памяти, 3 прохода, ~140 мс |
| Где лежат люди | D1 на Cloudflare | SQLite на вашем сервере |
| Что видит браузер | те же четыре пути, те же слова в отказах | **то же самое** |

Фронт переключается одной переменной сборки. Пока её нет — работает старый путь
через Cloudflare. Дня «всё падает и переключаем» не будет.

## Шаг 1. Поддомен

Cloudflare → Domains → `flamingo.plus` → **DNS** → *Add record*:

| Поле | Значение |
|---|---|
| Type | `A` |
| Name | `api` |
| IPv4 | `82.147.71.204` |
| Proxy status | **Proxied** (оранжевое облако) |

⚠️ Именно **Proxied**. Тогда сертификат для `api.flamingo.plus` выпускает и продлевает
Cloudflare, и на сервере с Let's Encrypt возиться не надо.

## Шаг 2. Сертификат между Cloudflare и сервером

SSL/TLS → **Origin Server** → *Create Certificate* → согласиться с предложенным →
сохранить два куска в `/etc/ssl/flamingo/` на сервере:
`origin.pem` (сертификат) и `origin.key` (ключ, права `600`).

Затем SSL/TLS → **Overview** → режим **Full (strict)**.

⚠️ Режим *Flexible* не ставить: он шифрует только половину пути, и пароли поедут
от Cloudflare к вашему серверу открытым текстом.

## Шаг 3. Код и зависимости на сервере

```
git clone git@github.com:ahmtgv/flamingo.git /opt/flamingo
cd /opt/flamingo/backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt gunicorn
```

## Шаг 4. Настройки

Создать `/opt/flamingo/backend/.env`:

```
SECRET_KEY=<вывод: python3 -c "import secrets; print(secrets.token_urlsafe(64))">
DEBUG=0
ALLOWED_HOSTS=api.flamingo.plus
CORS_ALLOWED_ORIGINS=https://flamingo.plus
SESSION_COOKIE_DOMAIN=.flamingo.plus
DB_PATH=/var/lib/flamingo/flamingo.sqlite3
LIVEKIT_URL=
LIVEKIT_API_KEY=
LIVEKIT_API_SECRET=
```

🔴 `SESSION_COOKIE_DOMAIN` — ровно `.flamingo.plus`, **с точкой впереди**. Без точки
куку увидит только `api`, и человека будет выкидывать после каждого перехода.

🔴 `SECRET_KEY` подписывает куки сессий. Сменить можно в любой момент, но все вошедшие
окажутся выйденными. Мне его показывать не надо.

Завести базу:

```
mkdir -p /var/lib/flamingo
.venv/bin/python manage.py migrate
```

## Шаг 5. Автозапуск

`/etc/systemd/system/flamingo.service`:

```
[Unit]
Description=Flamingo · учётные записи
After=network.target

[Service]
WorkingDirectory=/opt/flamingo/backend
ExecStart=/opt/flamingo/backend/.venv/bin/gunicorn config.wsgi:application \
  --bind 127.0.0.1:8000 --workers 3 --timeout 30
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```

```
systemctl enable --now flamingo
```

🔴 **Три работника — не случайное число.** Каждая проверка пароля берёт 64 МБ памяти
(так устроен argon2id: перебор на видеокарте упирается именно в память). Три работника —
это потолок примерно в 200 МБ, когда весь класс входит разом. Больше работников —
больше памяти; на маленькой машине это первое, что кончится.

## Шаг 6. nginx перед ним

```
server {
    listen 443 ssl;
    server_name api.flamingo.plus;
    ssl_certificate     /etc/ssl/flamingo/origin.pem;
    ssl_certificate_key /etc/ssl/flamingo/origin.key;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

## Шаг 7. Проверка ДО переключения

С любой машины:

```
curl -s https://api.flamingo.plus/api/auth/me
```

Должно ответить `{"person": null}`. Если ответило — сервер жив, база на месте.

## Шаг 8. Переключение фронта

Cloudflare → Pages → `flamingo` → Settings → **Variables and Secrets** →
переменная сборки (не Secret):

| Имя | Значение |
|---|---|
| `VITE_AUTH_URL` | `https://api.flamingo.plus` |

Затем Deployments → верхний выкат → «···» → **Retry deployment**.

**Откат:** убрать переменную и выкатить снова. Учётные записи вернутся на Cloudflare
(и снова упрутся в 10 мс), но сайт не сломается.

## Шаг 9. Бэкап

База — один файл. В `cron` раз в сутки:

```
sqlite3 /var/lib/flamingo/flamingo.sqlite3 ".backup '/var/backups/flamingo-$(date +\%F).sqlite3'"
```

🔴 Это единственное место, где живут учётные записи. Cloudflare их больше не хранит.
Пропадёт файл — пропадут все, кто завёлся.

## Что теперь на вас

Это цена выбранного пути, названная один раз:

- **обновления безопасности** самого сервера и Django;
- **бэкап базы** — см. шаг 9;
- **что сервер жив.** Упадёт он — вход перестанет работать. Урок по ссылке
  при этом продолжит работать: он идёт через Cloudflare и LiveKit и сервера не знает.

## Чего ещё нет

- **Восстановление пароля.** Нужна отправка почты — отдельное решение.
- **Ограничение попыток входа.** Сейчас пароль можно подбирать сколько угодно.
  На своём сервере это чинится просто, но это отдельная работа.
